结论

V3 不是重写 v2，而是把 v2 已验证的「机制词表 + 契约门禁」从事后清单升级为引擎骨架的类型系统：技能从「各自写 handler」改为「声明式 SkillDef + 分面」。M0–M5 全部落地，119 用例 + 987 v1 oracle 全绿，B0（7 技能）已迁移，B1–B20 在新窗口继续。

  1. engines.txt 的「事件驱动 + 结算栈」方向对，但缺 9 大块；v2 已补出，却分散在 30 多个 hook 点，这是病灶。
  2. 296 个技能里，转换技与「回合内主动 + 回合外响应」应拆成多个技能面（face），其余用声明式订阅解决。
  3. 机制词表 49 条、手牌武器「武器 = 特殊技能注入」是继承基线，不是重造对象。
  4. PPO 蓝图（自对弈 + 隐状态 + 信念状态）是 Suphx / Pluribus / DouZero 验证过的正路，是目标不是子问题实验；V3 只交「RL-ready 接口 + 观测编码」。

三张牌修正 + 藤甲二维伤害（已对齐）

白银狮子：伤害恒 1 + 离开装备区（弃置/移动）回 1 体力。藤甲：火 +1；普通杀无效（含转化普杀）；南蛮/万箭无效；雷正常；其他伤害/流失有效。方天画戟：额外至多 2 目标（合计 1–3）。藤甲判定 = damage_kind（fire/thunder/normal）× source_kind（slash/nanman/wanjian/duel/skill/hp_loss）两维。

授予技缺口（已补权威描述）

11 个授予技：8 已实现（攻心/荐言/急袭/思蜀/和弦/柔弦/烈弦/激弦）+ 3 未实现（怀柔/清侧/排异，只有文本无效果）。他人侧可发动（非主公技）= 2（陷嗣移逆出杀、蛊惑质疑）。V3 需统一「他人侧/授予」机制覆盖全部。

AI：PPO 是目标，V3 只交接口

PPO 蓝图（自对弈 + 隐状态 + 信念状态）是 Suphx / Pluribus / DouZero 验证过的正路，是最终目标。V3 的 AI 交付物是「RL-ready 接口 + 观测编码」，不是 PPO 实现。

上一版的担忧蓝图给出的解法结论
部分可观测（他人手牌身份隐藏）RNN / GRU / Transformer 隐状态 + 对手建模 + 信念状态有解
对手非平稳Self-Play 策略池 + Elo 采样 + 熵正则有解
合法集动态legal_actions = 物理规则掩码（引擎已天然实现）免费
多目标奖励按身份不同，每座位终局 +1 / 0简化
局时长 / 稀疏奖励GAE λ≈0.95 + 只给终局奖励有解
多人 5–8自对弈控制全部座位有解
  1. 先锁三接口 ↗

    V3 产出观测 / 掩码 / 奖励 schema，Gym 风格、SB3 无关

  2. BC 蒸馏预热 ↗

  3. 自对弈 PPO ↗

    SB3 起步，必要时迁 RLlib；目标就是它

四个 V3 就要埋桩的真问题

观测张量序列化（160 牌变长 + padding + 可见性掩码）是硬骨头；内奸奖励不平衡需单独归一化；局内确定性规则奖励（杀反摸 3 / 主杀忠弃牌）要进但分层；计算预算需 BC warm start，别从零 self-play。
