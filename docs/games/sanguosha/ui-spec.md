# 三国杀视图与交互规格（UI Spec）

> 状态：**v1.0 设计定稿待实现**（2026-10-27，用户逐条确认 Q1–Q10）。实现阶段：P2 只做数据契约，**P3 做页面**。
> 关联：ADR-0020（Web 优先与三分区）、`special-zones.md`（观星）、`interaction-primitives.md`（`ordered` 原语）、`data-model.md` §4、`development-plan.md` P2/P3、`docs/modules/web.md`（端形态与基线）。
> 本文只定义**端侧契约**（布局/手势/浮层/观星交互）；引擎语义见 `legal-actions.md` / `state-machine.md`。

## 1. 范围

| 项 | 本期口径 |
|---|---|
| 端 | **浏览器优先**：同一页面兼容 PC 浏览器与手机浏览器（响应式 + autosize），不建原生壳 |
| 交互承载 | Web 页；观星用指针拖拽，其余全部点击 |
| 非目标 | 原生 App / RN / Tauri 壳（延后）；美术资源；动画体系；无障碍完整达标（仅保证键盘可用 + 文本态） |
| 数据来源 | 引擎三分区投影（`public_board` / `player_area` / `special_zones`）；前端不推导规则，不猜合法动作 |

## 2. 端与基线

| 项 | 结论 |
|---|---|
| 目标内核 | **Chromium ≥ 88 / iOS Safari ≥ 14**（「2020 年之后的版本」的落地口径） |
| 构建 target | 沿用 `build:client` 现有评估，最终 target 由 `es2020` 降到 `es2017`（待实测） |
| 允许使用 | flex/grid + `gap`、`aspect-ratio`、CSS 变量、`clamp()/min()`、`position: sticky/fixed`、Pointer Events、`setPointerCapture`、`touch-action` |
| 禁止使用 | `:has()`、容器查询（Container Queries）、`dvh/svh`（用 `vh` + `env(safe-area-inset-*)`）、`popover`、`scrollbar-gutter`、原生 HTML5 拖放（`draggable` / `dragstart`） |
| 桥依赖 | 无。token 只走 URL query + `/state`，不落 localStorage、不依赖原生桥 |
| 刷新 | 沿用 10s 轮询 + 激活即刷 + 失败退避；页面与 `/state` 一律 `no-store` |
| 降级 | 无 JS → 文本态（含观星槽位文字描述与顺序提交入口）；触屏/鼠标同一套 Pointer 代码 |

## 3. 布局

### 3.1 总骨架（左右分栏）

```
┌───────────────┬──────────────────────────────────────────┐
│ 辅助区(可折叠) │ 游戏区                                    │
│ · 出牌历史     │ ┌──────────────────────────────────────┐ │
│ · 阶段/轮次    │ │ 公共区（对手座位环绕 + 中央牌堆/弃牌） │ │
│ · 本局信息     │ ├──────────────────────────────────────┤ │
│               │ │ 个人武将区（武将/技能/装备/判定/手牌/操作条）│ │
└───────────────┴──────────────────────────────────────────┘
```

- 左侧辅助区：`width: clamp(220px, 22vw, 360px)`；**手机端默认折叠**为左边缘图标，点击以抽屉 + 遮罩展开。
- 右侧游戏区：**上下结构** —— 上方公共区、下方个人武将区。
- 比例：公共区 `flex: 1 1 55%`、个人区 `flex: 0 0 auto`（内容撑开，最小高度可容纳手牌 + 操作条）。

### 3.2 公共区座位布局

- **8 人局基准**：左 2、上 3、右 2（共 7 位他人），自己位于下方个人区。
- 他人数量 `m = 人数 − 1`（5–8 人局 → m = 4–7）分配公式：

| m | 左 | 上 | 右 | 例 |
|---|---|---|---|---|
| 4 | 1 | 2 | 1 | 5 人局 |
| 5 | 1 | 3 | 1 | 6 人局 |
| 6 | 2 | 3 | 1 | 7 人局 |
| 7 | 2 | 3 | 2 | 8 人局 |

`上 = min(3, ceil(m/2))`，`左 = ceil((m − 上)/2)`，`右 = m − 上 − 左`。

- **填位顺序**（与自己左手侧起、逆时针一致）：左列**自下而上** → 上排**自左而右** → 右列**自上而下**。
- 槽位用**百分比绝对定位**在公共区容器内（`left/top` 为 %，卡牌尺寸用 `clamp()`），容器按 `aspect-ratio` 自适应 → 天然 autosize，无需 JS 测量。
- 上排不足 3 人时：3 槽取居中的子集（2 人 → 左上 + 右上；1 人 → 中）。
- **中央区**：牌堆（背面 + 余量数字，不可翻看）、弃牌堆（顶部一张 + 数量，点击开浮层列表）、公共特殊区（判定展示等）。

## 4. 区域内容与可达性

| 区域 | 内容 | 可交互 |
|---|---|---|
| 公共区 · 他人 | **完整武将牌**（名/势力/体力/技能名）+ 手牌背面 + 数量标记 + 装备 5 槽小标记 + 判定区小图标 | 小标记/武将牌可查看详情；**不可代他人操作** |
| 公共区 · 中央 | 牌堆余量、弃牌堆、公共特殊区 | 弃牌堆查看；牌堆只读 |
| 个人区 · 武将 | 己方武将牌（完整）+ 技能按钮（可用/不可用/已用） | 点武将 → 详情浮层；技能按钮按 `legal_actions` 启停 |
| 个人区 · 手牌 | 正面小卡：点数 + 花色 + 牌名文字 | 短按选中/取消；长按看详情 |
| 个人区 · 装备 | 5 槽小标记（武器/护具/进攻马/防御马/特殊） | 长按看详情 |
| 个人区 · 判定 | 延时锦囊**一字图标**：乐（乐不思蜀）/ 兵（兵粮寸断）/ 雷（闪电） | 长按看详情 |
| 个人区 · 操作条 | 选中项摘要 + 「确认打出」（未选中时置灰）+ 取消选择 + 结束出牌 | 按钮 |
| 浮层 | 详情/特殊区 | 关闭 |

- **判定区图标顺序**：从左到右依次摆放，**后进的在左边**（即最左 = 栈顶 = 先判定，符合 LIFO）。
- 一字图标（乐/兵/雷）用文字 + 颜色区分，不用纯图形（保证无图资源时可用）。
- 手牌区**横滑**优先，卡牌最小宽度保证可点（≥ 44px 触摸目标）。

## 5. 手势模型（统一，指针事件）

> 只用 Pointer Events（`pointerdown/move/up/cancel`），**不用 HTML5 DnD**。所有判定见 `apps/web` 端侧常量，可按实测微调。

| 手势 | 判定 | 语义 |
|---|---|---|
| 短按 | `up − down < 400ms` 且位移 ≤ 8px | 点击：手牌选中/取消；观星牌移入另一列首个空槽；按钮/槽正常点击；判定图标无操作 |
| 长按 | `up − down ≥ 400ms` 且位移 ≤ 8px | 打开详情浮层（手牌/装备/判定/其他小标记） |
| 长按 + 移动 | 长按激活后移动 | **仅观星**：拖拽卡牌（吸附/交换） |
| 移动 > 8px（未长按） | 立即取消本次按击 | 视为滚动意图：不选中、不开浮层、不拖拽 |

补充规则：

1. **点击判定在 `up`**（不是 `down`）：`down` 只记录时间与坐标。
2. `pointercancel` / 滚动开始 → 结束按击，不产生点击。
3. 手牌选中态：已有选中时短按另一张 → 取消原选中并选中新卡；短按已选中卡 → 取消选中。
4. 未选中任何牌时「确认打出」为**禁用态**；按钮可用性由 `legal_actions` 决定，前端不自行推断。
5. 观星内长按激活拖拽后**原地松手 = 无操作**（不触发点击、不移动牌）。
6. 触摸目标 ≥ 44px；PC 端 `@media (hover: hover)` 才显示 hover 高亮。
7. 禁止在游戏区做页面级滚动；手牌区/左侧辅助区/浮层内容可各自滚动，`overscroll-behavior: contain`。
8. **长按到时（400ms）即给反馈并置标记**：观星在此刻激活拖拽（否则无法「先长按再移动」）；手牌/装备/判定在此刻打开详情浮层。`up` 时若已置长按标记 → 不产生点击（结果与「按 `up` 时长判定」一致，仅提前反馈保证手感）。
9. 已知取舍：手牌横滑若「按住不动 >400ms 再滑」会被判为长按（开详情）；真机实测若误触率高，再调阈值或改为「移动 >8px 即取消长按」。

## 6. 浮层规范

- **所有特殊区域与详情统一为居中浮层**：观星、五谷丰登、判定展示、濒死求桃、无懈链、牌面详情、武将详情、弃牌堆列表。
- 结构：全屏遮罩（`rgba(0,0,0,.55)`）+ 居中卡片；单例容器 `position: fixed; inset: 0; z-index: 100`。
- 尺寸：普通详情 `max-width: min(92vw, 720px)`、`max-height: min(80vh, 640px)`；观星 `max-width: min(96vw, 900px)`。
- 关闭：点遮罩 / 关闭按钮 / `Esc`；安卓返回键按 `history` 处理为关闭浮层。
- 滚动锁：打开时 `body { overflow: hidden }`，内容区 `overscroll-behavior: contain`。
- **同时只显示一层浮层**；交互浮层（如观星）内需要看牌详情时，用浮层内的二级面板/展开区，不叠第二层。
- 焦点：打开时焦点移入，关闭后还原；`role="dialog"` + `aria-modal="true"`；Tab 在浮层内循环。

## 7. 观星（`guanxing`）交互规格

### 7.1 结构

- 浮层内 **2 列 × 5 槽**，槽位 id 固定：`L1..L5`（左，牌堆顶侧）、`R1..R5`（右，牌堆底侧）。
- **槽位数恒为 10**，与实际抽到的张数无关（技能张数 ≤ 5）。
- 一槽一牌，不堆叠。

### 7.2 初始

- 取 `k = min(N, 5)` 张（N 由技能给出，本项目内 N ≤ 5），依次填入 `L1..Lk`；`L1` = 牌堆顶第 1 张。
- 初始右列为空。

### 7.3 操作

| 操作 | 结果 |
|---|---|
| 短按左列牌 | 移入右列**自上而下第一个空槽** |
| 短按右列牌 | 移入左列**自上而下第一个空槽** |
| 长按 + 拖动 → 空槽 | 放入（源槽变空） |
| 长按 + 拖动 → 有牌槽（同列或跨列） | **两张交换** |
| 释放点超出吸附范围 | **回原槽** |
| 落回原槽 | 无操作 |
| 目标列已满 | 不会发生（总牌数 ≤ 5 < 10），实现仍保留 no-op 保护 |

- **吸附判定**：以卡牌中心与各槽中心的距离最小者为准；阈值 `T = 槽短边 × 10%`（CSS 变量可调，真机实测再调）；`d ≤ T` 才吸附，否则无效返回。
- 拖动中：原槽留空位提示、卡牌跟手 + 抬升阴影、候选槽高亮；超出阈值时无高亮。
- 长按激活拖拽前不移动卡牌（仅按下反馈）。
- 提供「重置」回到初始分布；观星不可取消（技能必须结算），关闭浮层后可从个人 pending 条重新打开。

### 7.4 结算与提交

- 提交时**每列跳过空槽并按上到下压紧**（拖动可能在一列中间留下空槽）。
- 最终牌堆 = 左列（`L1→L5`，跳过空）**接**右列（`R1→R5`，跳过空）；左列第一张成为**新牌堆顶**，右列最后一张成为**最底**。
- 一次提交，**无部分状态**；动作 id 为 `arrange:<card_instance_id,csv>`（按最终顺序）。
- 观星期间这些牌属于处理区，**牌数守恒**断言需覆盖（牌堆 + 手牌 + 装备 + 判定 + 处理区 + 弃牌堆）。

### 7.5 数据形状（P2 契约，P2.5 引擎已实现）

> 引擎侧（`resolve_zone.rs`）：准备阶段自动进入、`slots` 由引擎维护、`arrange:<csv>` 一次性提交并校验（张数/去重/来源/仍处理区）；端侧只做草稿与排序，不得自行推导规则。

```jsonc
"special_zones": {
  "guanxing": {
    "id": "guanxing",
    "owner": "<openid>",
    "visibility": "owner",
    "rows": 5,
    "cols": 2,
    "slots": { "L1": "c3", "L2": "c1", "L3": null, "L4": null, "L5": null,
               "R1": null, "R2": null, "R3": null, "R4": null, "R5": null },
    "rev": 3,
    "interaction": { "kind": "ordered", "commit": "arrange" }
  }
}
```

- 状态机：`created → arranging → submitted`；无超时；断线/刷新按 `slots` 恢复，不重新发牌。
- 他人视图不含该区域（`visibility: owner`）；公共视图只暴露「某人在观星」这类进度信息（可选，不得暴露牌面）。

### 7.6 可测试的纯函数（P3 实现，先在 P2 定接口）

| 函数 | 语义 |
|---|---|
| `settle(slots) → OrderedIds` | 跳过空槽、按列压紧，产出最终顺序 |
| `applyDrop(slots, from, point, geometry) → slots` | 吸附判定 + 放置/交换/回原位 |
| `applyTap(slots, from) → slots` | 移入另一列首个空槽 |

## 8. 响应式与 autosize

| 断点 | 布局要点 |
|---|---|
| `< 640px` | 左辅助区折叠为抽屉；公共区占上半屏（座位百分比定位 + 卡牌 `clamp()` 缩放）；个人区手牌横滑；操作条固定底部；安全区留白 |
| `640–1023px` | 左辅助区可展开；公共区/个人区上下比例略偏公共区；手牌横滑 |
| `≥ 1024px` | 左辅助区常驻；游戏区双结构不变；手牌横排（不滚动，超出则缩小到下限再横滑）；hover 高亮 |

- 尺寸单位：根字号 `html { font-size: clamp(14px, 0.6vw + 10px, 18px) }`；卡牌 `aspect-ratio: 3/4` + `width: clamp(...)`。
- 不用 JS 计算布局（避免 resize 抖动）；仅浮层开关与拖拽坐标用 JS。
- 横竖屏切换：桌面/横屏复用同一 DOM 结构，只切 CSS。

## 9. 锦囊交互（P2.3）

### 9.1 无懈可击链

- 居中浮层：标题「无懈可击」；展示被抵消的 `root`（牌名 + 使用者/判定者）、已打出的层（玩家 + 牌名）、当前被询问者。
- **有手牌但手里没有无懈时，仍显示「不出」按钮**（显式 pass，不自动跳过——保留思考/犹豫的心理博弈）；**无手牌（且无替代选项）的玩家不会被询问**（引擎自动跳过，2026-10-28 裁定）。
- 无超时；Esc/点遮罩**不关闭**（必须显式选择，防误关）；可滚动查看层列表。
- 同一玩家可能在后续层再次被询问；层号 1、2、3… 标注。

### 9.2 判定前无懈

- 判定阶段：先弹「判定前」浮层（延时锦囊 + 判定者 + 无懈链）。
- 被无懈 → 不亮判定牌，直接按 `rules-rulings.md` §4.3 处理（乐/兵进弃牌堆；闪电流转左手第一个玩家）。
- 未被无懈 → 亮判定牌 + 结果（沿用 `judge` 特殊区展示）。

### 9.3 拿牌选择（顺手牵羊 / 过河拆桥）

- 浮层标题：锦囊名 + 目标玩家；两种锦囊共用同一组件。
- 三区分组列表：
  - 装备区：5 槽（空槽不显示或灰显），显示牌名/花色点数；
  - 手牌：**单条「随机手牌（N 张）」**，不展示牌面；
  - 判定区：延时锦囊列表（栈顶在前，标「先判」）。
- 点选即提交（无二次确认）；无可选牌时提示并直接结算（牌进弃牌堆）。
- 结果写入出牌历史并公开（顺手：获得的牌名；过河：弃置的牌名）。
- 获得手牌后，若超过持有上限 → 立刻进入弃牌 pending。

### 9.4 借刀杀人（二阶段目标）

> **P3 实现口径**：候选由引擎在 `legal_actions` 阶段过滤（无武器者不出现），因此页面**没有禁用态候选**；
> 点选即提交（无二次确认）。灰/红边框属端侧视觉增强，留待 P4/真机验证后按需补。

- 第一步（借刀对象 A）：候选 = 其他存活且**装备区有武器**的角色；无武器者**灰边框 + 禁用**；选中者**红边框**；再次点击 A 取消选择。
- 第二步（杀目标 B）：候选 = A **攻击范围内**的其他存活角色（不含 A 且不能是使用者自己？按牌面：由使用者指定一名 A 攻击范围内的角色）；范围外**灰边框禁用**；选中红边框；点击 A 可取消并回到第一步。
- 底部操作条：「确认」仅在 A、B 都选中后启用；「取消」清空两段选择回到初始状态（不产生部分状态）。
- 确认后：无懈链 → 询问 A 是否打出【杀】（**即使 A 无杀也显示「不出」**，且由 A 自己选具体哪张杀，不随机代选）→ A 不出则武器交给使用者。

### 9.5 五谷丰登（P2.5 引擎已实现 / P3 UI）

- 浮层展示亮出的牌；**释放者排在最左先选**，其余按座位（左手侧）依次；当前选择者高亮，其他人只读。
- 已被选的牌变灰并标注选择者；剩余牌在结束后进弃牌堆。

### 9.6 技能多选（制衡 / 后续仁德等）

- 手牌区进入「多选态」：点牌切换选中（选中描边/抬升），底部操作条显示「已选 N 张 + 确认 + 取消」。
- 确认前可反复增减；`取消` 仅在允许 0 张的技能出现（制衡最少 1 张，无取消）。
- 与普通出牌互斥：多选态下点击牌不触发「打出」，只切换选中。

### 9.7 主公技接力与突袭

- **激将/护驾**：本人响应待办里出现「发动激将/护驾」按钮；点击后浮层提示「等待同势力角色响应」，逐个展示被询问者与可选【杀】/【闪】，被询问者可不出（回到本人响应）。
- **突袭**：摸牌阶段先弹「是否发动突袭」；选择发动后进入目标选择（最多 2 名、可确认提前结束），获得的手牌进入本人手牌区并公开张数变化。
- **仁德/离间**：使用 §9.6 的多选态；确认后分别进入「选择交给谁」/「选择两名男性角色」浮层。
- **八卦阵/仁王盾**：需要【闪】时若装备八卦阵，操作条多一个「八卦阵判定」按钮（判定结果在浮层/历史中展示）；青釭剑来源时该按钮不出现。
