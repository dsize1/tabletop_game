# 三国杀特殊交互区设计

> 状态：**登记表 v0.1（2026-10-25）**。规则：**所有特殊区域都必须先在本文件登记并完成设计评审，再进入实现**（用户 2026-10-25 裁定）。
> 关联：`rules-rulings.md`、`data-model.md`（§4.2 视图三分区）、`development-plan.md`（P2/P3）、ADR-0020（Web 优先与区域三分）。

## 1. 什么是特殊交互区

公共局面区（只读）和玩家个人资源区（本人手牌/装备/技能/私有标记）之外，由**技能或牌**临时创建的交互区域，例如：

- 观星：查看并排序牌堆顶若干张；
- 五谷丰登：亮出若干牌，按座位顺序每人选一张；
- 判定展示：亮出判定牌与判定结果；
- 濒死求桃：按响应顺序逐个询问是否出桃；
- 无懈可击链：按响应顺序询问是否打出无懈可击。

特殊区**不放进公共区或某人的个人区**，而是单独的 `special_zones` 投影；可见性由创建者声明（`owner` / `public`，预留 `all` / `team`）。

## 2. 设计模板（每个特殊区必须写全）

| 字段 | 说明 |
|---|---|
| `id` | 区域标识（如 `guanxing` / `wugu` / `judge` / `dying` / `wuxie_chain`） |
| 名称 | 玩家可见名称 |
| 触发 | 哪个技能/牌、什么时机创建 |
| 参与者 | 谁可操作（单人 / 按座位顺序 / 全体） |
| 可见性 | `owner` / `public`（预留 `all` / `team`） |
| 区域内容 | 牌/选项/计数/状态，是否加密 |
| 进入 | 创建条件、初始化数据、事件 |
| 交互 | 原语：`one` / `many(min,max)` / `partition` / `ordered`；步数与主体（单步/级联/接力/异步） |
| 退出 | 完成/取消/超时（**无超时**，见规则裁定）后的状态迁移 |
| 回滚 | 交互中断/非法动作时是否可重试，是否留部分状态（默认不允许） |
| 事件 | 进入/每步/退出写入 `game_events` 的 payload |
| 端侧 | Web 个人资源区/特殊区如何渲染；WebView 复用；Q 后置（只给链接） |
| 测试 | 规则用例、可见性用例、回放用例 |

## 4. 区域与视图契约

- 引擎状态：`data.special_zones = { <id>: { owner?, visibility, ... } }`（见 `data-model.md` §4.1）。
- `get_state`：只返回 `visibility='public'` 的特殊区。
- `get_player_view`：返回本人可见的特殊区（`owner` 匹配本人 + 公共）。
- 公共区永远只读；特殊区的交互只在 Web 个人资源区/特殊区发起；Q 后置（牌局链接进入 Web）。

## 5. 观星（首个落地样例，设计定稿 2026-10-27）

按 §2 模板逐项填写；交互细节（吸附阈值、手势）见 `ui-spec.md` §5/§7。

| 字段 | 内容 |
|---|---|
| `id` | `guanxing` |
| 名称 | 观星 |
| 触发 | 技能（诸葛亮「观星」等）在准备阶段发动 |
| 参与者 | 技能拥有者单人 |
| 可见性 | `owner`（他人不可见牌面；公共视图最多提示「正在观星」） |
| 区域内容 | **2 列 × 5 槽固定**：`L1..L5`（左，牌堆顶侧）/ `R1..R5`（右，牌堆底侧）；一槽一牌；实际张数 `k = min(N,5)`（本项目 N ≤ 5），初始填 `L1..Lk` |
| 进入 | 技能触发 → 从牌堆顶取 k 张（计入处理区）→ 写 `special_zones.guanxing`（`rev` 初始 1）→ 事件 `guanxing_enter` |
| 交互 | `ordered`；**短按**牌 = 移入另一列自上而下第一个空槽；**长按拖动** = 落空槽放入 / 落有牌槽交换 / 超距回原位；吸附阈值 = 槽短边 × 10%（可调） |
| 退出 | 「确认」一次性提交：每列跳过空槽并上到下压紧，左列接右列 → 新牌堆顶为左列首张、最底为右列末张；动作 `arrange:<csv>`；写 `guanxing_submit` 事件；**不可取消**（技能必须结算） |
| 回滚 | 不允许部分状态；非法动作/断线刷新按 `slots` 原样恢复，不重新发牌 |
| 事件 | `guanxing_enter`（牌 id 列表、rev）/ `guanxing_submit`（最终顺序、rev）；不记录中间拖动 |
| 端侧 | 居中浮层（单层）+ 10 槽；拖动中高亮候选槽；提供「重置」；Q 后置（仅链接）；浮层内禁止页面滚动 |
| 测试 | 牌数守恒（含处理区）、顺序确定性、空槽压缩、交换/超距回原位、`owner` 可见性、回放一致 |

数据形状：

```jsonc
"special_zones": { "guanxing": {
  "owner": "<openid>", "visibility": "owner", "rows": 5, "cols": 2,
  "slots": { "L1": "c3", "L2": "c1", "L3": null, "L4": null, "L5": null,
             "R1": null, "R2": null, "R3": null, "R4": null, "R5": null },
  "rev": 1, "interaction": { "kind": "ordered", "commit": "arrange" }
} }
```

## 6. 五谷丰登（首个多主体样例，待细化）

- **语义**：亮出 N 张牌，按当前玩家左手侧开始的座位顺序，每人选择 1 张；无牌可选时跳过。
- **交互**：`one` + 异步等待（跨玩家）；排队显示当前轮到谁。
- **可见性**：`public`（候选牌公开，选择结果公开）。
- **退出**：所有人选完（或牌被选完）后，剩余牌进弃牌堆；写 `wugu` 事件。
- **测试**：座位顺序、死亡跳过、牌数守恒、回放。

### 6.1 无懈可击链（wuxie_chain，P2.3 落地）

| 字段 | 内容 |
|---|---|
| `id` / 名称 | `wuxie_chain` / 无懈可击链 |
| 触发 | 锦囊即将生效前；延时锦囊判定阶段判定前 |
| 参与者 | 按座位顺序询问**所有存活玩家**（不跳过手中没有无懈者） |
| 可见性 | `public`（链上每一层打出者与牌公开） |
| 区域内容 | `root`（被抵消的效果）、`layers`（每层：玩家 + 无懈牌）、`current_ask`、`cancelled` |
| 进入 | 引擎创建 `Wuxie` 结算帧 → 从原锦囊使用者（判定场景为判定者）左手侧开始询问 |
| 交互 | `respond:<无懈牌>` / `pass`；每次有人打出无懈：层数 +1、重新从起点询问；连续一整轮无人出牌 → 结束 |
| 退出 | 奇偶层数判定 root 是否生效（奇=抵消）；无懈牌入弃牌堆；回到上一层结算帧 |
| 回滚 | 链中不产生部分状态（牌停处理区）；链结束一次性入弃牌堆 |
| 事件 | `wuxie_play`（层数、玩家、牌）/ `wuxie_chain_end`（层数、是否抵消） |
| 端侧 | 居中浮层，展示链层数与当前询问者；**无无懈者也可 pass**；Q 后置 |
| 测试 | 单层/三层嵌套、同一玩家连续响应、AOE 每目标独立、判定前无懈、奇偶判定 |

### 6.2 拿牌选择（pick_card，顺手牵羊 / 过河拆桥共用）

| 字段 | 内容 |
|---|---|
| `id` / 名称 | `pick_card` / 拿牌选择 |
| 触发 | 顺手牵羊、过河拆桥目标确定并通过无懈后 |
| 参与者 | 锦囊使用者 |
| 可见性 | `owner`（交互仅使用者；**结果公开**：日志记录获得/弃置的牌） |
| 区域内容 | 目标玩家的：装备区全部槽位（明牌）、手牌（**单个"随机手牌"选项**）、判定区延时锦囊（明牌） |
| 进入 | 无懈链结束且未抵消 → 创建 `PickCard` 帧 |
| 交互 | `one`：`pick:equip:<slot>` / `pick:hand` / `pick:judge:<card_id>`；手牌由引擎随机抽取并写入事件 |
| 退出 | 顺手：牌进入使用者手牌；过河：牌进弃牌堆；写入 `pick_card` 事件 |
| 回滚 | 选中即结算，不可撤销；无合法目标（区域全空）→ 牌直接进弃牌堆 |
| 端侧 | 浮层展示目标三区；手牌区只显示"随机手牌"；点选即提交 |
| 测试 | 三区各选一次、空区域（无合法选项）、手牌随机性（固定种子可复现）、牌数守恒 |
