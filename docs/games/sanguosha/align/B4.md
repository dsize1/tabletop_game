## 夺刀（`duodao` / normal）— `implemented`

**【1 官方原文】** 当其他角色使用【杀】对你造成伤害后，你可以弃置一张牌获得其装备区里的武器牌。
来源：`heroes.json#gid=180`

**【2 现实现（按代码陈述）】**
- 触发在 `damage_after`（濒死结算之后、受伤者仍存活）：受伤者拥有夺刀、来源≠自己、来源**装备区有武器**、受伤者**手牌非空**、且造成伤害的牌是物理【杀】（`def ∈ sha/huo_sha/lei_sha`）。
- 询问受伤者：列出**全部手牌** + 「不发动夺刀」；选定后弃置该牌（`discard_by`，原因=受伤者）。
- 随后把来源武器从装备区移入受伤者手牌（触发旋风/枭姬类失去装备钩子 + 手牌上限检查 `cap_hand`）。

**【1 官方原文】** 锁定技，当你于回合内使用牌时，你本回合计算与其他角色的距离-1。当你于回合内使用仅指定单一目标的【杀】或普通锦囊牌时，若你与所有其他角色的距离均为1，你依次选择至多两项，令此牌：
 1.目标数+1；2.无视防具；
 3.不能被抵消；4.造成伤害后，你摸一张牌。
来源：`heroes.json#gid=324`

**【2 现实现（按代码陈述）】**
- 锁定技第一段：回合内**每使用一张牌**就 `bump_counter("benxi")`（使用牌处），`effective_distance` 减去该值 → 本回合每张牌让距离 -1（可累加）。
- 第二段：使用【杀】时若 `benxi_all_distance_one`（对所有其他角色距离都 ≤1）→ **先**压入奔袭帧选择至多两项强化（勾选/取消；`confirm` 至少 1 项，`pass` = 不强化）。
- 四个强化：目标数 +1 / 无视防具（`benxi_armor`）/ 不能被抵消（`mark_sha_no_respond`）/ 造成伤害后摸 1（`benxi_draw`，在伤害后钩子里消费）。
- 选择完成后取出该【杀】并 `start_sha_flags` 进入正常【杀】结算（强化标记在结算时读取/清零）。
- 只覆盖【杀】：普通锦囊**不**提供强化选项。
置信度：`verified`（verified=已核对代码路径；inferred=推断，未找到唯一路径）

**【3 与原文差异】**
- 原文「使用**仅指定单一目标的【杀】或普通锦囊牌**时」→ 实现只处理【杀】，普通锦囊（顺手/过河/决斗/火攻…）完全没接。
- 「仅指定单一目标」的前置未显式校验：实现是「使用【杀】之前」询问强化（此时尚未选目标），因此无法真正判断「仅单一目标」。
- 「距离 -1」每张牌累加且无上限（可能把距离减到 1 以下），原文未写是否封顶 1。
- 「目标数 +1」在没有额外合法目标时仍可选（选完可能无目标可加）。
- 「不能被抵消」用 `unresponsive`（令【杀】不可被响应），与「不能被无懈抵消」语义接近但走的是同一开关。

**【4 疑点】**
- `Q1` 第二段的适用范围是否包含「仅指定单一目标的普通锦囊」？
  - 候选：A. 包含（顺手牵羊/过河拆桥/决斗/火攻…） / B. 只有【杀】（现实现）
  - 倾向：**A**（原文明确写「或普通锦囊牌」。）
  - 影响：使用入口（锦囊路径）+ 强化项对锦囊的生效方式。
  - 裁定：**A（【杀】与普通锦囊都适用；判定「仅指定单一目标」读**目标列表**——【杀】也要有目标列表，兼容方天画戟/界太史慈多目标杀）**
- `Q2` 「本回合计算与其他角色的距离 -1」是否可累加到下限以下？
  - 候选：A. 可累加，距离最低到 1（现实现未封顶） / B. 最多 -1（固定）
  - 倾向：**A**（原文「当你…使用牌时…距离-1」按每张牌累加；实际距离最小 1。）
  - 影响：距离计算封顶 + 用例。
  - 裁定：**C（第一段相当于**自带进攻马**：固定 -1，可与装备的进攻马叠加，不是每张牌累加）**
- `Q3` 「目标数+1」在没有额外合法目标时是否仍可选？
  - 候选：A. 可选（没有额外目标则无效果） / B. 不可选（不提供该选项）
  - 倾向：**B**（避免玩家选了无效强化；但需与官方口径对齐。）
  - 影响：选项集合 + 反例用例。
  - 裁定：**「目标数 +1」必须是**合法目标**才可选/生效（没有额外合法目标则该选项不生效）**

**【5 机制依赖】** `turn-window`、`target-list`、`card-attributes`

**【6 动画 / UI 期望】**
- 提示文案：通用询问：奔袭选择至多两项强化｜浮层交互：多选（4 项强化，可勾选/取消）+ 确认｜动效 key：本期不做｜逐张亮牌：本期不做｜群侧播报：本期不做

**【7 对齐后描述（权威）】**
**锁定技**。第一段：你本回合计算与其他角色的距离 **-1**（等价**自带进攻马**，固定 -1，可与装备的进攻马叠加；**不是**每使用一张牌累加）。第二段：当你于回合内使用**仅指定单一目标**的【杀】或普通锦囊牌时（「单一目标」读**目标列表**长度 = 1；【杀】同样走目标列表，兼容方天画戟/界太史慈的多目标【杀】），若你与所有其他角色的距离均为 1，你依次选择至多两项，令此牌：1. 目标数 +1（**必须是合法目标**才生效）；2. 无视防具；3. 不能被抵消；4. 造成伤害后你摸一张牌。

**断言**
- 正例：回合内距离固定 -1（不是每张牌累加；可与进攻马叠加，下限 1）；单目标【杀】/普通锦囊且距离均为 1 → 选至多两项强化；「目标数+1」只在有合法额外目标时提供
- 反例：多目标（目标列表长度 ≠ 1）不触发；非吴懿回合不触发；没有额外合法目标时不给「目标数+1」
- 实现锚点：sanguosha2::skills::b4::BENXI（`Game::distance` 固定 -1 + `TargetChosen`）｜用例：b4::benxi_distance_is_minus_one_not_per_card、b4::benxi_offers_options_for_single_target_sha、b4::benxi_skipped_for_multi_target_or_other_player

# 周仓 `sgs_hero_325`（1 技能）

## 忠勇（`zhongyong` / normal）— `implemented`

**【1 官方原文】** 当你使用【杀】后，你可以将此【杀】或目标角色响应的【闪】交给一名其他角色，若此牌为红色，其可以对你攻击范围内一名角色使用一张【杀】。
来源：`heroes.json#gid=325`

**【2 现实现（按代码陈述）】**
- 触发：【杀】结算完毕（`resolve.rs` Sha 帧结算处 `zhongyong_on_sha_finished`），若使用者拥有忠勇、有目标、且该【杀】或目标打出的【闪】**当前在弃牌堆** → 压入忠勇帧。
- 询问：`give:sha`（此【杀】）/ `give:shan`（目标打出的【闪】）→ 选牌后进入选接收者（其他角色，排除自己）。
- 接收者获得该牌（从弃牌堆取出直接进手牌 + 手牌上限检查）。
- 若牌为**红色**且存在「接收者之外、在**忠勇拥有者**攻击范围内」的角色 → 追加询问：令接收者视为对其中一名使用一张【杀】（无距离、虚拟）。
- 两张牌都不在弃牌堆（被其他技能拿走）→ 不询问。
- M2 接线：接收者「视为使用【杀】」已改为真实结算（可选目标、响应、伤害全真实）。
置信度：`verified`（verified=已核对代码路径；inferred=推断，未找到唯一路径）

**【3 与原文差异】**
- 「其**可以**对你攻击范围内一名角色使用一张【杀】」→ 实现直接**视为**使用（不问接收者是否愿意，无「可以」出口）。
- 交出牌用 `hand.push`（从弃牌堆直接进手牌），不产生「获得」事件 → 视图/牌区事件链不完整。
- 「接收者使用【杀】」的虚拟杀无承载牌（`card` 为空），不能被花色类技能引用。
- 「你攻击范围内」用的是**周仓**（拥有者）的攻击范围 ✓；但若接收者=周仓本人则不额外询问（接收者排除自己）。

**【4 疑点】**
- `Q1` 「其可以…使用一张【杀】」是否要询问接收者（发动/放弃）？
  - 候选：A. 要询问（原文「可以」，由接收者决定） / B. 直接视为使用（现实现）
  - 倾向：**A**（`wording-can` 硬规则；且消耗接收者的【杀】次数对他有影响。）
  - 影响：接收者侧交互 + 次数计数器联动。
  - 裁定：**A（询问接收者是否使用【杀】）**
- `Q2` 「你攻击范围内」按谁的攻击范围判定？
  - 候选：A. 周仓（技能拥有者，现实现） / B. 接收者
  - 倾向：**A**（原文「其可以对你攻击范围内一名角色使用一张【杀】」——「你」= 周仓。）
  - 影响：范围判定 + 用例。
  - 裁定：**A（周仓的攻击范围）**
- `Q3` 交出的牌是否需要产生「获得」事件（视图/牌区事件一致）？
  - 候选：A. 需要（走 `gain` 语义） / B. 直接进手牌（现实现）
  - 倾向：**A**（「交给」是获得动作，视图与牌区事件应一致。）
  - 影响：牌区事件链 + 与「落英/行殇」等获得类钩子的交互。
  - 裁定：**A（交出的牌走「获得」语义，产生获得事件）**

**【5 机制依赖】** `card-attributes`、`use-vs-play`、`virtual-card`、`wording-can`

**【6 动画 / UI 期望】**
- 提示文案：本期不做（沿用通用文案）｜浮层交互：本期不做（沿用通用文案）｜动效 key：本期不做（沿用通用文案）｜逐张亮牌：本期不做（沿用通用文案）｜群侧播报：本期不做（沿用通用文案）

**【7 对齐后描述（权威）】**
当你使用【杀】后，你可以将此【杀】或目标角色响应的【闪】**交给**一名其他角色（走「获得」语义，产生获得事件）；若此牌为红色，**其可以**（由接收者选择发动/放弃）对你攻击范围（**周仓的攻击范围**）内一名角色使用一张【杀】。

**断言**
- 正例：使用【杀】后把此【杀】/其打出的【闪】交给其他角色（走「获得」语义）；红色牌 → **由接收者**决定是否对周仓攻击范围内一名角色使用【杀】
- 反例：牌已被其他技能拿走 → 不询问；黑色牌不给接收者追加【杀】
- 实现锚点：sanguosha2::skills::b4::ZHONGYONG（`skills::on_sha_finished`）｜用例：b4::zhongyong_gives_sha_and_asks_receiver_for_red_card、b4::zhongyong_not_offered_when_card_gone
