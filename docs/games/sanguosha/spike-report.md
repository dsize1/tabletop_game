### 1.1 LOC 明细

```
新 crate（src）        2,201 行  其中内核 1,114 / 技能 676 / 展示+插件 422（mod 行数重合计入前两类）
新 crate（tests）        384 行  15 条用例（5.0 条/技能）

旧引擎同技能专属代码      781 行（良姻 278 / 箜声 163 / 贞良 340）= 260 行/技能
新引擎同技能专属代码      676 行（良姻 / 箜声 / 贞良）= 225 行/技能
```

**结论**：LOC 不是本次重写的主要收益（只降 14%，未达 50% 目标）。真实收益在
**缺陷类别消除**与**用例密度**：旧引擎这 3 个技能在 B2 一天内产生 6 个缺陷
（就地压帧 ×2、触发点漏接线 ×2、帧丢牌 ×1、两处各写一半 ×1），新内核在结构上
不允许前 5 类，第 6 类由判例门禁覆盖。

## 2. 六类缺陷 → 结构性对策（注入实验结果）

| # | 缺陷模式（plan §8.5） | 新内核如何让它不可能/必被抓 | 证据 |
|---|---|---|---|
| A | 触发点逐路径硬编码 | 牌区唯一出口 `move_card` + 语义 helper 上报事件；技能只订阅 | `gate_kernel_has_no_skill_branch`（内核禁止出现技能名/`== "skill:`） |
| B | 就地压帧被父帧 pop | 技能 handler 只返回 `Step`，栈只由 `advance` 改 | 同上 + 全部 3 技能多阶段流（`Step::Next`） |
| C | 帧里暂存牌丢失 | 牌区唯一归属；帧暂存 = `Zone::Frame`；栈空仍有帧牌即报错 | `gate_conservation_after_every_step` |
| D | 同一规则两处各写一半 | `active()` 单一状态源；legal/execute 调同一 `can_*`；订阅由注册表派生 | `gate_view_derived_from_registry`、`zhenliang_yang_is_legal_and_executable` |
| E | 文案与语义相反 | `POutcome` 枚举 → 唯一文案表（含无懈两条互斥文案） | `gate_presentation_texts_disjoint` |
| F | 白名单/枚举式 UI | 动作/订阅/转换态全部派生，无第二份清单 | 同上 |

另：`gate_single_deferred_queue` 断言 state 里**没有** `*_queue` 字段——旧引擎的
6 条 per-skill 队列在新内核里"写不出来"。

## 4. 尚未覆盖（迁移时必须补）

1. **卡牌效果本体**（杀/闪/桃/锦囊结算、濒死、判定、无懈链）——spike 只做技能层；
2. **视图/引擎协议细节**（`public_state` / `player_view` / 摘要 / 9 类区展示）；
3. **AI 接口**（观测流 / 决策点枚举 / 剪枝候选 / 决策日志）；
4. **迁移对拍工具**（旧引擎 replay → 新内核逐动作摘要比对）；
5. **48 个技能级 spike 之外的机制**（化身、蛊惑、国战接缝）。

## 5. 结论与条件

**GO**：可以按「新 crate 逐批迁移」推进，但有三条附加条件（已写入计划）：

1. **接受 LOC 目标修正**：由「≤50%」改为「≤旧引擎同技能 + 用例密度 ≥2 倍 + 缺陷类 6/6 消除」；
2. **B0 实现前补齐内核缺口**：牌/锦囊结算、濒死、判定、视图、AI 接口（按 B0 的 7 技能需要哪些先做哪些）；
3. **每个迁移技能都必须带反例断言**（良姻式误触发是最大的历史缺陷源）。

### 7.2 K1 新增的内核能力（B0 需要）

- **濒死流程**（`kernel/flow.rs`）：求桃顺序 = 自己 → 左手侧；`酒` 仅自救；
  锁定技钩子（`skills::dying_hooks`）先于求桃；**技能收益可延后到脱困后**（`Stage::AfterDying`）。
- **死亡**：`Death` 事件（行殇等订阅）+ **DeathCleanup 延迟项**（排在技能触发之后，先让行殇拿牌再清理）。
- **判定**：`judge_card`（亮出 → 处理区 → `JudgeRevealed`）/ `judge_effective`（`JudgeEffective` → 颂威）。
- **无懈窗口**：`start_wuxie` + 技能提供替代选项（`wuxie_opts` / `wuxie_use`），层数奇偶 → 互斥文案。
- **帧阶段语义修正**：`Step::Next/Done` 现在作用于**发起帧索引**（handler 内压入的子帧不会被父帧误改），
  并新增 `Step::NeedAt`（切阶段 + 同时询问），修掉「答完又走同一段」的一类隐患。
