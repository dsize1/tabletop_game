# 三国杀规则引擎与权限校验

> 状态：**P0 草案 v0.1（2026-10-26）**。配套 `rules.md`、`state-machine.md`、`legal-actions.md`、`docs/modules/game-engine.md`、ADR-0008/0016。
> 核心：**引擎是最后防线**，不信任 agent / 决策模型 / Web / 中台；所有写动作无条件重校验。

## 1. 校验链（写入路径）

```
execute_action(room_id, player_id, action)
  1. 对局状态校验：存在、Active、阶段匹配
  2. 动作解析：id 语法合法、牌实例/技能/选项存在
  3. 合法性：在 legal_actions 当前集合内
  4. 权限：actor/回合/资源/目标归属
  5. 前置条件：距离、次数、体力、手牌、装备槽
  6. 执行：pending 推进或状态迁移
  7. 事件溯源：append game_events + 更新快照（同一事务）
  8. 返回 ActionResult（message/finished/state/events）
```

任一步失败 → `EngineError` → 文本 `错误: <原因>`；**不修改状态、不产生事件**。

## 2. 权限矩阵

| 操作 | 允许者 | 校验 |
|---|---|---|
| `lobby:join` | 群成员 | 未在座位、群无 Active 竞争对局 |
| `lobby:leave` | 在座玩家、`phase=lobby` | 房主退出 → 本局废弃 |
| `lobby:kick:<id>` | 房主 | 目标在座、`phase=lobby` |
| `lobby:start` | 房主 | 人数 5–8、身份配比可生成 |
| `lobby:abort` | 房主 | 任意 Active 阶段（不结算） |
| `lobby:add_bot` | 房主 | 座位未满 |
| `setup:choose_general` | 当前选将玩家 | 武将在候选池且 `live` |
| `play:<card>` | 当前回合玩家 | 手牌/合法区域、阶段 `play`、牌条件 |
| `target:*` | 当前 `pending.actor` | 目标在合法集、数量/距离/阵营符合 |
| `discard:*` | 当前 `pending.actor` | 牌在本人手牌、数量正确 |
| `respond:*` | 当前 `pending.actor` | 在响应窗口、牌可响应 |
| `pass` | 当前 `pending.actor` | 可选放弃（必选响应除外） |
| `skill:<code>` | 技能拥有者/当前 actor | 技能已获得、触发条件、次数/标记 |
| `resume` / `hint` | 任意在局玩家 | 只读，不改状态 |

## 3. 合法性校验明细

### 3.1 通用

- `status == Active`；`phase` 与动作匹配；
- `player_id` 在座位且存活（死亡角色不能行动）；
- `action` 必须由当前 `legal_actions` 生成；禁止构造未出现的 id；
- 牌实例存在且位于允许区域（手牌/装备区/判定区，按动作）；
- 目标存在、存活、非自己（除非牌/技能允许）；
- 次数/标记/体力/手牌数满足牌面与技能。

### 3.2 距离与范围

- 攻击范围 = 武器范围（默认 1）+ 技能修正；距离按存活角色座位计算；
- 攻击距离 = 武器范围 + 进攻马 + 技能；防御距离 = 基础 + 防御马 + 技能；顺手牵羊/兵粮寸断不含武器范围；技能（马术等）叠加；
- 距离/范围由引擎计算，**不接受上游传入**；
- 距离最小为 1（自己为 0）。

### 3.3 次数与资源

| 资源 | 规则 |
|---|---|
| 【杀】次数 | 默认每出牌阶段 1 次；诸葛连弩/技能可无限或额外 |
| 【酒】 | 每回合限一次（出牌阶段） |
| 装备槽 | 武器/防具/进攻马/防御马/特殊（木牛流马）各 1；替换旧牌入弃牌堆 |
| 手牌持有上限 | 任何时刻 `config.max_hand_cards`（默认 20）；超出时立即弃至上限 |
| 弃牌阶段手牌上限 | **当前体力值**（技能可改） |
| 判定区 | 不能有同名延时锦囊 |

### 3.4 响应窗口

- 只有 `pending.actor` 可响应；响应顺序由引擎按座位计算；
- 响应牌必须满足牌面（闪/无懈/桃/酒/杀）或技能转化；
- 无懈链：从原锦囊使用者左手侧开始；每次有人打出无懈，重新从该使用者左手侧开始；允许同一玩家多次响应；直到无人响应。
- 濒死求桃：每次回复后重新检查体力，未脱离继续询问。

## 4. 执行与事件

### 4.1 状态迁移

- 单步动作只做一件事：推进 pending 或完成一次牌/技能结算；
- 产生多个询问时进 `pending_queue`，不递归改状态；
- 伤害/死亡/胜负在同一结算栈内按规则顺序处理。

### 4.2 事件

- 每个成功动作至少 1 条事件；随机结果（洗牌/判定/随机弃牌）必须入 payload；
- `game_events` append-only；`game_state.version` = 最后事件 seq（ADR-0004/0008）；
- 事件类型见 `state-machine.md` §6；事件 payload 必须足够重放。

### 4.3 幂等与并发

- 写动作按 `room_id` 串行（agent-gateway per-session 队列 + 引擎锁）；
- 同一 `event_id` 唯一键去重；
- 不允许并发修改同一房间；重复提交同一动作应被状态校验拒绝。

## 5. 视图与防泄露

- 引擎内部完整状态；`public_state` / `player_view` 按 `data-model.md` §4.2 投影；
- 错误信息不得包含：他人手牌、未公开身份、牌堆顺序、加密选项真义；
- 加密选项只下发一次性代码；真义仅在本人 `player_view`；
- 日志/事件可用完整状态，但出站消息只使用投影。

## 6. 反作弊与边界

- 不信任上游的 `player_id`：以消息发送者 openid 为准，Web 以 token scope 为准；
- 不信任距离/目标/牌实例：一律重算/重查；
- 不信任中台：中台只提供元数据，规则判定不读中台实时配置；
- 不信任 n8n/工作台：运行时不加载流程图；
- 死亡/终局后拒绝写动作；`resume`/`hint` 只读。

## 7. 错误类型

| 类型 | 示例 |
|---|---|
| `NotFound` | 对局/牌/技能不存在 |
| `IllegalAction` | 动作不在合法集、阶段不符、次数用尽、距离不足 |
| `PermissionDenied` | 未轮到你、非房主、非 pending.actor、目标不可选 |
| `InvalidState` | 对局已结束、身份未分配、pending 冲突 |
| `Internal` | 不应发生；记录日志并回滚 |

## 8. 测试要求

- 每个动作：合法路径 + 非法路径（越权/阶段/资源/距离/目标）；
- 每个武将技能 ≥3 条用例 + 1 条跨技能交互；
- 不变量：牌数守恒、体力上下限、手牌上限、死亡后无动作、身份唯一；
- 回放一致性：同 seed + 同动作序列 → 同状态/事件；
- 视图用例：公共视图无隐藏信息、个人视图越权 403、特殊区可见性。
