# 道具：筹码（Chips）

> 状态：草案 v0.2。来源：用户规则 一 / 二.3 / 四(弃回合) / 五.2 / C2 / D1 / F2 / G1 / H1 / H2。

## 基本属性

- **计分**：终局每个筹码折 **$1 万**（用户规则 一）。
- **初始**：每位玩家 2 枚（用户规则 二.3）。
- **每轮追加**：第二轮、第三轮开始时每位玩家 +2 枚（用户规则 五.2）。
- **支付用途**：
  - 对投掷结果不满意 → 支付 1 枚收回骰子并跳过本回合（用户规则 三.注 1）；
  - C2「厄运降临」→ 骰子最少的玩家向银行支付 $5 万，资产不足（含筹码）则支付全部资产；
  - 其它小游戏奖励/消耗（D1/F2/G1/H2 等）。

## 发放/消耗来源汇总

| 小游戏 | 获得 | 消耗 |
|---|---|---|
| D1 发薪愉快 | 1–2 筹码（视符合条件的赌场数） | — |
| F2 危机就是转机 | 可选 1 筹码 | — |
| G1 黑色摸彩箱 | 摸彩奖励可能含 2 筹码 | — |
| H1 好骰难求 | 1–2 筹码（1–2 号格） | — |
| H2 我的抉择 | 1 点/2 点 → 1/2 筹码 | — |
| C2 厄运降临 | — | 支付 $5 万或全部资产 |
| 通用 | — | 弃回合 1 筹码 |

## 数据模型映射

- `seats[].chips: u32`；银行筹码池 `bank_chips`（若需追踪，否则可视为无限）。
- 筹码变动（获得/支付）须作为事件写入，保证复盘可重放。
- 【待确认】筹码不足时的边界（弃回合不可选；C2 支付全部资产的确切含义）。

## 与「钞票」的关系

- 筹码与钞票**分开持有**，仅在终局计分时折算相加（用户规则 一）。
- 小游戏奖励的「$X 万」若表述为钞票，则计入钞票；若为筹码则计入筹码（如 D1 的 1/2 筹码 vs ≥3 时的钞票）。
- H1 好骰难求（裁定 2026-10-17）：格位由**重投**决定，1–2 格给**筹码**，3–6 格给**钞票 $3/4/5/6 万**（因 1 筹码 = $1 万，等价 1–6 万递增阶梯，重投期望 3.5 万）。
