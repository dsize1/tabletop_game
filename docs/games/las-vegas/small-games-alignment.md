## 1. 每阶段的固定流程

1. **我呈报**：该小游戏的①简单说明（怎么玩/为什么有趣）②拟实现方式（触发时机、状态字段、交互动作、结算入账点、边界处理）③当前代码现状与已知 GAP ④需要你裁定的问题清单。
2. **你给详细步骤**：可编号，可口语；错别字/措辞不当由我修正。
3. **我对齐**：逐条比对「你的步骤 vs 我的实现口径」，输出一致性结论。
   - **一致** → 我把你的步骤改写为规则说明，写入 `docs/games/las-vegas/rules.md`（该编号条目下，含实现口径注记），并更新 `props/small-games.md` / `legal-actions.md` / `data-structure.md`。
   - **不一致** → 我列出差异点请你确认；确认后**同时**更新规则与代码。
4. **实现与验证**：改 `crates/engines/las-vegas/src/{sg.rs,lib.rs,ai.rs}` + `apps/web/src/render.ts`（如需展示），补测试；`cargo test --workspace` + `apps/web npm test` 全绿。
5. **置为 ✅ 完成**，进入下一阶段（一次只讨论一个小游戏）。

## 2. 结算形式（重要：先定分类，再谈每块）

**现状：结算形式是硬编码的，没有声明式定义。** 具体硬编码点：

| 位置 | 硬编码内容 |
|---|---|
| `lib.rs::settle_round` | 固定顺序：`b1_pre_settle` → `g1_prepare`（G1 分堆/选堆交互，完成后重新进入结算）→ 逐赌场 `{c2_pre_casino → settle_casino}` → `post_settle`（C1 兑换）→ `settle_extras`（G2 游戏场 / H2 金框 / H1 格位） |
| `sg.rs::on_place` | `match` 里按 id 直接调用 C1/D1/A2 的自动效果 |
| `sg.rs::trigger_interactive` | `match` 里按 id 直接挂 A1/B2/E1/F1/F2/H1/H2 的 pending |
| `sg.rs::legal_turn_sg` / `resolve_turn_sg` | 按 id 硬编码 D2 / G2 的回合内动作 |

建议正式定义 **7 类结算时机**（`SgTiming`），把上面 4 处改成「按时机表派发」：

| 时机码 | 名称 | 发生点 | 已归入的小游戏 |
|---|---|---|---|
| **T1** | 立即结算（交互/自动触发当下入账） | `on_place` / `resolve` 内 | A1、A2、B2、D1、E1（箭头奖励）、F2（a/b 组）、H2（1–3 点）、C1（拿标记） |
| **T2** | 轮次结算前·全局一次 | `pre_settle_round` | B1 |
| **T3** | 轮次结算前·逐赌场 | `pre_settle_casino`（移除平手前） | C2 |
| **T4** | 轮次结算前·交互（暂停结算） | `pre_settle_pending` → 完成后恢复 | G1（分堆→选堆） |
| **T5** | 钞票分配后·统一结算 | `post_allocate` | G2（游戏场）、H1（格位）、H2（金框） |
| **T6** | 钞票分配后·标记兑换 | `post_allocate_marker` | C1（大奖标记 → $10 万） |
| **T7** | 持续状态（无独立结算） | 只影响赌场比较/动作可用性 | D2（特权）、E1（禁止标记）、E2（酒吧）、F1/F2（灰骰＝虚拟玩家） |
