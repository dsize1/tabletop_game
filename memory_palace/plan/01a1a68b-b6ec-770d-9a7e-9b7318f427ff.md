# 计划文档

## 计划

1. 任务边界：本轮只改 `apps/web`（客户端 TS/视图纯函数/静态素材/离线生成脚本/文档），**不改 Rust server 与引擎**；上一任务（卡面入中台）已完成并归档（commit 4834b35），本文件改为本轮新计划。
2. 现状分析（轮询）：`apps/web/src/client/sgs.ts` 的 `start()` 每 `pollMs`（默认 10s）无条件拉 `/state`；`applyState()` 每次都重建 `#sgs-app` 与侧栏。`player_area.pending` 只包含「本人待办」，`public_board.pending` 只给他人 pending；`actions` 是本人合法动作。服务端在执行动作后会连续推进 AI，故一次 `/state` 可能带回多条历史。
3. 现状分析（历史/特效数据源）：`public_board.history` 为全量正序 `{seq,turn,actor,text}`（上限 800），文本由引擎 `push_log` 生成：使用/打出牌、`受到 N 点{普通|火焰|雷电}伤害（体力 X）`、`【闪】抵消…`、`回复…`、`铁索连环…`、`雷击…`、`火攻…` 等。约束不改后端 → 客户端只能以 **历史文本解析 + 状态快照差分** 作为特效输入。
4. 轮询优化设计（已确认 60s）：新增纯函数 `awaitingLocal(data, actions)`（本人 `player_area.pending` 存在 / 选将未选且有候选 / 本人回合且 `actions` 非空）→ 命中时把轮询间隔从 10s 降到 **60s 保活**，并在状态栏显示「等待你的操作」；离开待办态立即恢复 10s。动作提交、visibility/focus/pageshow/online 仍立即刷新。
5. 重绘抑制：把「应用态签名」拆成 `appSig`（不含 history 的公共区/个人区/actions/special_zones）与 `sideSig`（history 末 seq + names）。`appSig` 未变时**不重建 `#sgs-app`**（保留选中/滚动/动画），仅按 `sideSig` 更新侧栏；两者都未变时只更新时间戳，避免频繁闪屏。
6. 特效层架构（不改变已有页面结构）：新增客户端 `client/sgs-fx.ts`，运行时 `document.createElement` 注入 `#sgs-fx-layer`（`position:fixed; inset:0; pointer-events:none; z-index:95`，低于现有浮层 100）与 `<style>`；现有 SSR/DOM 结构零改动。目标定位按座位实时读取 `.sgs-opponent[data-seat]` / `.sgs-personal` 的 `getBoundingClientRect()`；窗口缩放/重渲染后重新取。
7. 特效队列消费 + 输入锁定（已确认：不设跳过按钮）：首帧只记录 `lastHistorySeq` 基线，不回放旧历史；之后每次 `applyState` 取增量 → `buildFxCues(prev,next,ctx)` → 顺序播放。默认 400ms/条；队列 >6 时 220ms；同类同目标连续伤害合并为一条（带 ×N）；**上限 12 条：超过 12 条时只播放最近 12 条**（丢弃更早的），总时长 ≤3s。**消费期间锁定操作**：`body.sgs-fx-locked` 禁用 `#sgs-app` 内手牌/技能/确认/候选等交互（`pointer-events:none` + `submitAction/onClick/onTap` 前置 `fxLock` 检查），**允许滚动右侧历史**；同时**暂停轮询**，队列结束后立即 `refreshNow()` 并恢复 10s/60s 节奏。状态栏显示「行动结算中…」。页面隐藏或已有 pending 浮层时跳过播放并直接推进 seq。
8. 效果映射表（P0/P1 共用，纯函数可测）：① 普通伤害 → 目标座位挥刀 `slash`；② 打出【闪】→ 打出者 `dodge`（刀光落空 + 侧闪）；③ 使用【桃】/救援 → 目标 `peach` + 绿色回血光环；④ 使用【酒】→ 使用者 `wine`（酒葫芦 + 红/金怒气）；⑤ 雷电伤害（含雷杀/雷击/闪电）→ `thunder`（文本含「雷击/【闪电】」时加强为全屏闪 + 更粗雷柱）；⑥ 火焰伤害（含火杀/火攻）→ `fire`（火焰灼烧 + 橙色描边）；⑦ `铁索连环：属性伤害传导/对…结算` → 相关座位 `chain`（金色锁链缠绕）；⑧ 无法识别的 `回复/失去体力` → 轻量 `heal/lose` 光晕；解析失败静默降级，不抛错。
9. 映射兜底：除文本外，比较前后 `seats[].hp` 差分，确保「扣血必有受击特效」；文本用于区分元素/闪避/桃酒/铁索。座位解析优先 `player_id`（历史 actor 与伤害文本里的 pid），其次 `general_name`，再按 `seat_index` 兜底。
10. ComfyUI 资产管线（离线，一次性）：现状 = `C:\llm\ComfyUI` + Animagine XL 3.1 / SDXL base / SD1.5-inpaint；`custom_nodes` 仅 IPAdapter，`background_removal`/`frame_interpolation` 为空。P0 用 Animagine 生成静态 VFX（黑底/白底）→ 用户可直接改素材 → `sharp` 亮度键控/裁剪/缩放 → WebP；动画由 CSS transform/opacity/`steps()` 完成（火焰/雷击 2–4 帧 sprite sheet），不依赖 AnimateDiff。
11. 资产目录/两条命令：`slash / dodge / peach / wine / thunder_bolt / thunder_flash / fire / chain / heal`；工作流 `assets-src/comfyUI_workflow/fx-effects.json`、提示词 `assets-src/fx/prompts.json`、源图 `assets-src/fx/src/*.png`（本地，gitignore）、生成器 `apps/scripts/gen-fx-assets.mjs`。`npm run gen:fx` = ComfyUI 出图；`npm run gen:fx -- --assemble` = **不调 ComfyUI**，只把用户改过的源图重新键控/打包/生成 hash 文件 + `apps/web/src/view/sgs/fx-manifest.ts`，方便改完素材一键重打包。产物 `apps/web/public/fx/<name>-<hash>.webp`；web 加 `/fx-assets` 静态路由（immutable）。
12. 资产预算与门禁：单文件 ≤120KB、总 ≤1.2MB、尺寸 256–768；`check:fx-assets` 校验 `fx-manifest.ts` ↔ 文件 ↔ 大小/尺寸/帧数；`gen:fx` 支持 `--dry-run/--only/--assemble`；ComfyUI 不可用时只做校验不阻塞开发。
13. 性能/可访问性：特效只改 `transform/opacity/filter`，不触发布局；同时最多 2 个活动特效；`prefers-reduced-motion: reduce` 时退化为 150ms 描边/文字提示（不闪屏、不锁定超过 300ms）；雷电全屏闪烁 ≤2 次、透明度 ≤0.35；锁定层只挡操作不挡滚动，视觉上不遮盖版面。
14. 文档与 ADR：更新 `docs/modules/web.md`（轮询策略/`/fx-assets`/特效层/锁定语义）、`docs/games/sanguosha/ui-spec.md`（装饰性特效边界）、新增 `docs/games/sanguosha/props/fx-pipeline.md`（含 `--assemble` 改图流程）；新增 ADR-0037（客户端历史消费与特效层：无后端改动、文本解析契约、输入锁定、降级策略、资产预算）并登记 decisions/README。
15. 测试与验收：新增纯函数测试 `test-fx.mts`（历史样本 → cue、去重/合并/优先级/限流、awaiting 轮询策略）；`test:web` 全绿；Playwright 真机验收：AI 连推触发多 cue、**消费期间点击无提交且轮询暂停、结束后自动刷新恢复**、reduced-motion 退化、移动端无溢出；记录 `/state` 请求次数验证降频；素材门禁与构建全绿。
16. 【补充·动图与透明背景（2026-11-04 真机反馈后）】素材格式从「384px 静态 WebP + screen 混合」改为 **168×168、5 帧、80ms 的透明背景动画 WebP**（`normal` 混合）；由 `apps/scripts/fx_pack.py`（Pillow：亮度键控 → 裁空白 → 缩放/旋转/位移五帧 → alpha WebP）生成；单文件 ≤120KB、总 ≤1.2MB（当前 871KB）。运行时改为图片自身动 + CSS 淡入淡出，不再用 CSS 旋转/缩放叠加。
