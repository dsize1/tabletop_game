## 计划

1. P2 继续自 plan/01a1736d（P1 已验收）；本会话新开 P2 计划文档
2. P2 定位：引擎内核 + 标准身份局，产出「UI 无关」的状态/视图/动作契约；Web 页面与拖拽实现留在 P3
3. P2 分步：P2.1 骨架（crate/EnginePlugin/lobby/选将/牌堆/state schema v1/三分区投影）→ P2.2 回合与基本牌 → P2.3 濒死/奖惩/胜负 → P2.4 技能事件总线 + 交互原语（many min/max、多目标、ordered、响应队列）→ P2.5 special_zones 骨架（guanxing/wugu 设计稿落地准备）
4. 视图区交互结论（2026-10-27 技术评估）：WebView 内「点击」100% 可用；「拖拽」必须用 Pointer Events 自绘，HTML5 原生 DnD 不依赖；拖拽作为增强、点击（选牌→选目标）作为主路径与兜底
5. 视图区交互清单：武将区=点击（看技能/发动技能/翻面横置/标记）；特殊区观星=有序选择（拖拽排序 or 上移下移）；五谷/濒死/无懈/判定=点击单选 + 等待态，无需拖拽
6. P2 需要先定的跨端契约（UI 无关）：三分区字段、pending 结构与 actor/响应顺序、ordered 原语描述符、special_zones 可见性与状态机、动作 id 与批量提交边界
7. P2 验收：固定 seed 可复现、5 人无技能局可终局（含内奸分支）、牌数守恒、视图分区断言（公共无手牌/身份）、特殊区可见性、MCP 冒烟
8. 端侧决策（2026-10-27 用户确认）：端侧壳开发滞后；先用手机浏览器验证页面，再决定 Tauri/RN；页面必须同时兼容 PC 浏览器与手机浏览器（flex + autosize + 响应式断点，不用固定像素布局）
9. 拖拽范围收口：全局只有「观星」需要拖拽；其余区域（手牌/装备/判定/武将/五谷/濒死/无懈）一律点击，不做拖拽
10. 观星规格（用户 2026-10-27 给定）：特殊区浮层内 2 列 × 5 槽（左=牌堆顶侧、右=牌堆底侧，槽位数量固定）；初始取 min(N,5) 张依次填左列 L1..Lk；拖拽仅能落入 10 槽，吸附半径内进最近槽、超距回原位；落点已有牌则两张交换；点击卡牌则放入另一列从上到下第一个空槽；一槽一牌；最终牌堆 = L1..L5(跳过空) 接 R1..R5(跳过空)，L1 为新牌堆顶
11. 武将区/个人区规格（用户 2026-10-27 给定）：己方武将牌、手牌正面（点数+花色+牌名文字）、装备区、判定区；其他玩家（公共区）显示完整武将牌 + 手牌背面/数量 + 装备/判定小标记；装备/判定小标记点击展开完整牌；手牌点击看详情；出牌阶段「点牌选中 → 点确认打出」
12. 浮层约定（用户 2026-10-27 给定）：所有特殊区域（观星/五谷/濒死/无懈/判定展示/牌面详情/武将详情）统一为居中浮层，遮罩 + 关闭，禁止滚动穿透
