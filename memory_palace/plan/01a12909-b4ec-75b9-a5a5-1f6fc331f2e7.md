# 计划文档

## 计划

1. 目标：跑通 QQ 群消息全链路。分两阶段：P1 先「聊天验证」跑通 agent-gateway 与全链路出站；P2 再实现「猜拳（一轮）+ MCP 统一原语」。决策层本次 mock + 前缀低置信兜底（双通道交叉验证）。
2. 链路：QQ → qq-gateway(已有) → qq.raw(已有) → bot-adapter(新) → internal → agent-gateway(新,Node/TS) → [chat 桩 | 猜拳经 MCP stdio] → qq.push(新) → qq-gateway 出站(新) → QQ。
3. MCP：本次直接实现 MCP 统一原语（Rust MCP server 层 + agent-gateway MCP client，stdio），不走 HTTP 直连。
4. 猜拳：一轮对话，玩家消息自带手势，引擎内「模拟决策」解析手势、随机出拳判定、回复结果；game_id=rps；#play/#start 对猜拳等价，引擎需注意。
5. 自检：server GET /health 聚合 + 后台定时自检写缓存 + 热路径读缓存降级；不建独立 ops 服务。
6. dev 白名单：将白名单账号 member_openid 记录到配置，dev 意图校验用。
7. 技术选型定稿：Rust MCP server 用 rmcp 3.5.1；Node MCP client 用 @modelcontextprotocol/sdk 1.32.1。
8. dev 白名单：配置文件+环境变量（DEV_WHITELIST=member_openid 逗号分隔）。
9. 聊天桩行为：回显「[聊天桩] 收到：{msg}」。
10. 后续-1：聊天改「仅异步主动发送」——LLM 回复不走被动窗口，统一走主动消息（避免 3s 超时/被动窗口限制）。
11. 后续-2：聊天多轮对话——每群会话历史（Redis/内存）拼入 prompt。
12. 后续-3：决策层接入 SystemOne（StartLux-Decision-4B）替代 mock 关键词，解决「猜拳规则→开桌」「聊天→dev」等误判。
13. 后续-4：规则查询意图——「介绍/规则/玩法」类消息走 MCP get_rules，或交主持人 LLM 叙述。
14. 后续-5：引擎状态持久化恢复——game-engine-mcp 重启后从 SQLite game_state 恢复活跃对局；start_game 成功后 execute_action 失败需回滚/清理悬挂对局。
15. 后续-6：dev 白名单录入真实 openid（当前 DEV_WHITELIST 为空）。
