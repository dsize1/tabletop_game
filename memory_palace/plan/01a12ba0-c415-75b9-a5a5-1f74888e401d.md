# 计划文档

## 计划

1. 【统一键 sessionId】= pi 子会话 id = 计划文档 id（memory_palace/plan/{sessionId}.md，plan-memory 用 getSessionId 命名）= 后期 web 页标识；受理回执（被动回复）即携带 sessionId
2. 【按需唤醒·消息驱动】子会话不常驻连续执行：被人消息唤醒 → 执行一个工作段 → 停在 plan-workflow 内建人工门 → 落盘退出 → 等下条消息；停止点 = 围栏解除确认/完成确认/harness 发起/验收终结；执行 loop 内部连续跑完所有待办不逐条停
3. 【决策模型=人】dev 任务不套「LLM 只建议+引擎无条件校验」，而是「人决策（置信度 100%）+ 规则=计划与工作流 + 权限=开发者白名单」；与 game-engine 原语一致，仅把决策模型换成人
4. 【消息分工】被动回复=工作状态同步+引导人工推进（不展示计划内容）；主动推送=计划六分区正文（后期替换为 web 页短链）；受 external-constraints 频控约束
5. 【固定前缀命令·硬判断】人=决策模型置信度 100%，查询/决策命令走硬判断；查询命令支持参数（sessionId/状态），返回 sessionId+状态+title 三维；含「列出所有任务」「列出所有 MCP 能力（能力名+简述+使用方式+读/写）」
6. 【MCP 化（跳过阶段一直接做）】dev-task 引擎以 MCP 形式暴露（对齐 game-engine），含读写原语 + 状态机 + 白名单校验；host agent 与 web 页统一经 MCP/HTTP 查询
7. 【聊天多轮同时做】每群共享会话历史（chat_session_id=group_id），chatReply 注入历史上下文
8. 【后期 web 呈现】cloudflare tunnel + web 页渲染计划文档（标识=sessionId），鉴权同 game-engine 归一化（auth 短期 token）
9. 【状态机职责·已确认】子会话只做内容（生成计划/执行代码/写计划文档）；任务状态机由网关（路由人工固定前缀命令）+ Rust 引擎（权威状态+白名单校验）驱动；子会话不能自行改状态，confirm 仅由网关收到人命令后调 MCP 触发
10. 【消息桥输出·已确认】子会话每轮以面向用户汇报文本收尾，网关取 message_end 最终 assistant text 推 QQ；超 1500 字符的六分区计划主动分段推送（后期替换为 web 短链）
11. 【title 回填·已确认】任务 title 由子会话计划生成后调 MCP 回填（create_task 时可为空/占位）
12. 【MCP 读写标注·已确认】读写属性标注在 MCP tool 的 description 中，供「列出所有 MCP 能力」命令展示
13. 【聊天历史·已确认】专用表 chat_history，每群最近 20 条（配置化，后续可调）
14. 【子会话模型·已确认】复用主持人 LLM 的 provider/baseUrl/apiKey/model 四项；thinking 开关独立（聊天关、子会话开，chat.ts 的 thinking:disabled 不传导到子会话）
15. 【pi-sdk 集成·已确认】agent-gateway 需引入 pi-sdk（当前 index.ts 为手写消费者）：SessionManager.create/open + prompt/dispose 管理子会话
