43. ## BUG 修复：轮询后版图消失（2026-10-18）
三处加固（均已上线并回归）：
1. **旧 bundle 缓存**：`/assets/*` 原为 `max-age=1h`，浏览器可能拿旧 `app.js` 配新 HTML → 渲染异常。改为 `Cache-Control: no-cache` + ETag（每次校验，20KB 无压力）。
2. **无谓重建**：轮询返回的 `server_time` 每次变化，导致每 10s 重建整张 SVG/图片（弱网/低端 WebView 会闪成空白）。改为按 `{public,player,names}` 做签名比对，**数据没变就完全不碰 DOM**。
3. **替换后尺寸塌陷**：SVG 之前只靠 CSS `.board-svg{width:100%;height:auto}`，`innerHTML` 替换后部分 WebView 计算不出宽高比。改为 SVG 内联 `style="display:block;width:100%;height:auto"`；并给 `render()` 加 try/catch，渲染失败时保留上一帧而不是清空。
验证：Edge headless 35s（3 次轮询）版图稳定；`test:web` 全绿。用户侧需强刷一次（Ctrl+F5）以丢掉旧 bundle。

| D 视觉校验 | Qwen3-VL：识别板块文字/图标 → 校验 id 与编号、报告偏差 | 校验报告（人工可复核） |
| E 生成式清理（**待裁定**） | ComfyUI + SDXL/Flux（16G 可跑 fp8/schnell）：inpaint 去手/去桌面/补边；Real-ESRGAN 放大 | 干净底板/装饰贴图 |

- **能力边界必须说清**：llama.cpp 只能做 LLM/VLM（识别、描述、坐标建议、SVG 生成），**不能修图/生位图**。若要求「照片级干净素材」，D/E 阶段需要图像生成栈（ComfyUI+SDXL/Flux 或 stable-diffusion.cpp），这是本计划唯一需要新增的重型依赖。

## 交付分段

- **M1 版图渲染骨架（不含轮询）**：`view/` 共享模块 + SSR 首屏 + hash 切换 + 六边形布局（用占位色块也可跑通，素材陆续替换）。
- **M2 JSON 接口 + 轮询/激活刷新**：`/state` 接口 + 客户端 bundle + 10s 轮询（隐藏时暂停、错误退避）+ `最后更新` 时间戳。
- **M3 素材接入**：C 阶段产物 + manifest + debug 坐标层（`#debug`），版图还原真实外观。
- **M4 模型侧**：VLM 盘点/校验脚本 + （可选）生成式清理。
- **M5 跨端契约**：RN 映射守卫测试 + 文档。

## 本计划要交付什么

1. 新增**版图模式**（默认）：服务端生成内联 SVG 的拉斯维加斯牌面（赌场 6 列 × 骰子/大骰/灰骰 × 脱敏钞票 × 小游戏板块 × 玩家面板 × 公共区），保留现有**文本模式**，`?view=board|text` 双模式切换（默认 board），零客户端 JS。
2. 抽出**纯 TS 共享核心** `apps/board-core`（不依赖 DOM/Node/Express）：`types / theme / layout / scene`，输出平台无关 `BoardScene`（图元 IR + 绝对坐标 + 素材 id）。
3. Web 适配器 `apps/web/src/board/svg.ts`：`BoardScene → SVG 字符串`；未来 RN 适配器（react-native-svg）复用同一 scene（本期只出契约 + 映射规则 + 守卫测试，不建 RN 工程）。
4. 素材清单 `apps/web/public/board/manifest.json`（id → 文件/尺寸），本期先用纯矢量占位（无位图依赖），后续替换 PNG 不改渲染逻辑。
5. 本地模型选型落地：`Qwen3-VL-8B-Instruct-GGUF`（Q4_K_M 5.03GB + mmproj F16 1.16GB）跑在现有 llama.cpp（已确认二进制含 `qwen3vl` 支持，b7515）；仅用于**离线素材管线**（截图→元素/坐标清单、装饰 SVG 生成、manifest 命名），不参与实时渲染。
6. 文档与 ADR：`docs/modules/board-core.md`、`docs/games/las-vegas/props/board-layout.md`（几何口径）、ADR（版图渲染与 RN 复用策略）、更新 `docs/modules/web.md` / `docs/architecture.md` §1。

## 关键设计决策（预设，待人工确认后再实施）

- **渲染位置**：服务端渲 SVG（无客户端框架、低端机友好、可缓存），切换模式用链接整页刷新。
- **布局口径**：手机竖屏优先，6 个赌场 **3 列 × 2 行** 网格（编号 1–6 固定位置），玩家面板 2×2，公共区按「实际挂载的小游戏」条件渲染（无小游戏则不占位）。横向六列作为后续可选（同一 layout 常量切换）。
- **坐标全部预计算**：`layout.ts` 产出 absolute 坐标，adapter 只做「图元 → 宿主原语」机械映射（web: `<rect>/<circle>/<text>/<image>`；RN: `Rect/Circle/Text/Image`）。
- **颜色/身份**：按座位序号取固定 6 色（色盲友好、跨端一致）；bot 加「机器人」徽标；`names` 缺失用 `机器人N` 兜底。
- **脱敏遵循**：赌场钞票只画背面 + 张数；个人加密选项**不进版图**（保持在文本区/独立小节）。
- **素材缺席可运行**：manifest 缺 id 时回退矢量占位，绝不阻塞渲染。
- **性能**：单次 SVG 输出（预估 40–80KB），无图片请求即可开；素材后续走 `express.static` + 长缓存。
