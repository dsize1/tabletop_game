# 计划文档

## 计划

1. 【总体顺序（用户 2026-11-03 定稿）】① P6.4 决策日志 + 导出 + 回放（含 P6.3 验收记录归档）→ ② P7 Q 群接入收尾与真机验收 → ③ P8 上线验证 + 权鉴（含灰度开关/观测/运维手册）→ ④ 工作台 + 预览基座（P6.7/P5，优先落地「模板/预览/AI 调试」以服务武将验证）→ ⑤ 全武将系统化验证与缺陷修复（按批推进）。P6.5/P6.6（信念建模/搜索/自对弈强化）本轮不做。
2. 【缺陷优先轨道 B】用户真机验证中发现的问题不排队：每批先修 B 系列（附回归用例），再继续主线；其他武将问题先建立清单与优先级（用户反馈 > 自动审计 > 自对弈偶发），不阻塞 P6.4/P7/P8 主干。
3. 【P6.4-1 存储】`crates/storage` 新增 `game_decision_log` 表 + `(room_id, seq)` 索引（按 data-model §5 DDL，幂等 CREATE），API：`append_decision_log`（单条/批量）、`list_decision_log(room/game, since, limit)`；写失败只告警不阻塞对局；`SGS_DECISION_LOG_RATE`（0–1，默认 1）采样；`SGS_DECISION_LOG=0` 等价关闭。
4. 【P6.4-2 决策轨迹】三国杀 AI 暴露可记录的决策轨迹：`legal_actions`（完整集）、`candidates`（prune ≤26）、`chosen`、`score/confidence`、`reason`、`latency_ms`、`state_digest`；新增 `SgsPolicy::decide_traced` 或 `explain_with_trace`，driver/selfplay 复用同一实现，禁止两套打分逻辑。
5. 【P6.4-3 写点】server：人类动作写 `source=human`（candidates=null，legal/chosen 有值）；`drive_bots` 每个机器人动作写 `source=bot`（含 candidates/score/reason/latency），`seq` 对齐该步落库后的 `game_events.seq`；MCP `bot_action` 写 `source=bot`；`seq` 取动作返回的快照 version（落库失败时 seq=-1 仍可记录并标记）。
6. 【P6.4-4 导出】`apps/scripts/sgs-export-decisions.mjs`：按 `--room/--game/--limit/--since/--out` 导出 JSONL；`player_id` 做 sha256 前 16 位哈希；字段至少 room_id/game_id/seq/source/legal/candidates/chosen/confidence/latency_ms/created_at；输出确定性（按 seq,id 排序）。
7. 【P6.4-5 回放】`apps/scripts/sgs-replay.mjs`：以 `game_state` 快照 + `game_events` 逐步重放 + 叠加 decision log 时间线；支持 `--room/--from-seq/--to-seq/--step/--follow/--json`；断点续放；校验重放后 state digest 与快照一致（不一致报差异定位）。
8. 【P6.4-6 P6.3 归档】把 P6.3 真机验收结论、本次已修 B 系列（铁索/义绝/火攻/武圣/全 AI 续推/拼点残留/界制霸/决斗火雷杀）写入 development-plan P6.3 记录与 milestones，作为 P6.3 验收证据。
9. 【P7-1 命令矩阵审计】对三国杀 Q 群命令逐条核对：`#开局/#加入/#退出/#开始/#中断/#局面/#恢复/#网页/#中台/#武将包/#加机器人/#验证码#NNNN`；补齐未实现/文案不一致（重点 `#退出`、`#恢复`、`#中断` 后状态）；群内不出现逐动作选项、不泄露隐藏信息、不触发主动消息。
