# 计划文档

## 计划

1. **目标**：让 dev 任务线执行器（`agents/dev_executor`，DeepAgents）能用本项目 `.pi/skills` 与 playwright MCP，**不破坏 shadow 边界**（不写 `tabletop.db`、不出站、planner 无写权限）。
2. **现状（实测 deepagents 0.7.28）**：内置工具 `ls/read_file/write_file/edit_file/glob/grep/delete/execute(需 SandboxBackend)/task/异步 task 5 件/rubric_grader`；`planner.py` 用 `StateBackend()`（内存）+ `tools=[]` → **技能读不到**；**无 MCP 客户端**，`langchain-mcp-adapters` 未安装。
3. **方案 A（技能）**：`CompositeBackend(default=StateBackend(), routes={"/skills": FilesystemBackend(root_dir=<repo>/.pi/skills, virtual_mode=True)})` + `skills=[("/skills/", "项目技能")]`；`permissions=[FilesystemPermission(["read"], ["/skills"], "allow")]` 兜底只读；默认 backend 仍是内存 State，仓库其它路径不可达。
4. **方案 B（MCP）**：`langchain-mcp-adapters` 读 `.pi/mcp.json` 的 stdio 配置 → 转 LangChain tools 注入 `tools=[...]`；由 `DEV_MCP_SERVERS`（逗号分隔，默认空=关）控制，planner 默认不给 playwright（plan 阶段无浏览器需求）。
5. **方案 C（技能文件）**：`.pi/skills/plan-workflow/SKILL.md` 补 frontmatter `name`（否则被 SkillsMiddleware 跳过），并加「非 pi 运行时工具缺失」兼容小节。
6. **交付载体**：新增 `harness.py`（backend/技能源/MCP 加载）+ `tests/test_harness.py` + `tests/fake_mcp_server.py`（离线假 MCP）；文档 `agents/dev_executor/README.md`、`docs/modules/dev-task.md`、ADR-0014 追加 TD-14.7。
7. **不变量**：`plan` 节点仍只产出 6 分区计划、不写文件、不调 server；MCP/技能失败只降级（记录原因），不阻断出计划。
8. **harness loop 收尾（2026-10-20）**：4 项全部完成——自测清单、降级路径统一、`--print-skills`、技能/MCP 告警统一注记；待人工验收。
9. **人工验收通过（2026-10-20 用户确认）**：技能与 MCP 接入、harness 优化项均验收通过；剩余唯一延后项＝真实模型端到端跑一次（需 `LLM_API_KEY`），不阻塞交付。
