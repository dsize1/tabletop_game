# 计划文档

## 计划

1. 【批次划分】按 ADR-0007 分 5 个可独立验收的批次：①chat 键下沉+阶段裁剪 ②game 局面摘要注入 ③chat.log+chat_history 落库 ④画像表+日批蒸馏(本地9B按需)+全局注入 ⑤按线抽象+文档同步。**分段验收**：每批做完单独验证后再进下一批。
2. 【批次①—chat 内容隔离】Redis 键下沉：`chat:history:{group}:{openid}` 与 `chat:boundary:{group}:{openid}`；`index.ts` 所有读写带 `sender_id`；组装时对热 20 条按最近 `boundary` 裁到当前阶段（a1，20 条以外不留；无 boundary 则全取最近 20 条）。
3. 【批次②—game 背景】`game-engine-core` 的 `EnginePlugin` 增局面摘要方法；`game-engine-mcp` 暴露紧凑摘要原语；`narrateGame` 接收并注入摘要；`index.ts` game 分支取摘要。默认上限 ≤300 字符/关键字段（轮到谁、各玩家资源、赌场状态）。重心在 LLM 侧提示与约束，不灌原始 JSON。
4. 【批次③—冷存落库】agent-gateway 的 chat/game 分支发 `chat.log`（Redis Stream，MAXLEN ~1000，命名沿用现有风格）；`storage.chat_history` 迁移（openid/group_id/role/created_at + 索引）；`server` 消费 `chat.log` 落库（保持 SQLite 单写者；收 chat+game，不含 dev）。
5. 【批次④—全局画像】`user_profile` 表；`server` 增「读窗口」「upsert 画像」API；agent-gateway 凌晨 4:00（CHAT_TZ，自维护定时器）调度：**按需启动本地 9B**（模型位置固定 `/c/llm/llama.cpp-master/models/…`，不迁移）→ 生成候选事实/画像草稿 → **SystemOne 把关**（noul/score 决定保留与衰减）→ 确定性组装纯文本 → 写回 → **关闭 9B**。画像作为全局层注入 chat/game（为空则跳过）。
6. 【批次④-释放验证】9B 关闭后**与启动前快照对比**（GPU 显存 `nvidia-smi` + llama-server 进程/PID + 端口），确认完全释放；不达标则告警/重试 kill。
7. 【批次⑤—抽象与文档】把上下文来源按线抽象（chat/game 各一组装函数，为未来「砍 chat + 放开非 @ → 两线合并」留口子）；同步 `persistence.md`/`architecture.md`/`agent-gateway.md`/`mcp-primitives.md`/`decision-service.md`（9B 蒸馏服务）。
8. 【约束】数值型外部约束只引用 `external-constraints.md` 并标来源/验证状态；「凌晨 4 点」为工程约定（可配）。本地 9B 许可证需登记。
9. 【不做】非 @ 消息采集、群层记忆、会话摘要压缩（T3）、向量/语义召回（T4）。
