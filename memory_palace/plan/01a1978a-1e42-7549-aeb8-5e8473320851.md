# 计划文档

## 计划

1. 【P6 定位（分层，三层顺序推进，不并行）】短期 = P6.1–P6.4：Rust 规则引擎 + 行为树 + 启发式评估的 Baseline AI，能打完 5 人局并接入 Web 灰度通路（server 单写者自动推进 + `#加机器人` 放开）+ 决策日志/回放/导出 + 工作台·预览的必要条件；中期 = P6.5：读局面（身份后验 + 手牌信念）+ 关键决策一层搜索；后期 = P6.6+：自对弈强化 / 完美信息蒸馏 / 策略网络。基线参照拉斯维加斯 `crates/engines/las-vegas/src/ai/` 先例（`Policy` + 自对弈驱动 + 固定种子确定性）。
2. 【本轮不做（明确排除）】① SystemOne(StartLux-4B) 不参与 P6 走子——100 局自对弈需要本地高速确定性，且单次前向延迟与 ≤26 选项限制不适合批量回归（仅保留为离线对照实验，见待确定事项）；② 不做纯 MCTS（动作空间爆炸，改为候选剪枝 + 局部一层搜索）；③ 不做工作台本体（武将流程节点图设计器，属 P5）；④ 不改武将/牌堆/结算规则。
3. 【P6.0 前置：AI 可见信息视图 + 可观测性】在 `crates/engines/sanguosha/src/ai/` 建模块骨架（mod / view / eval / prune / tree / handlers / policy / selfplay / tests）。`ai/view.rs` 定义 `SgsView`：从 `SgsState` + viewer 投影出**可见信息**（公共座位 = 体力/手牌数/装备/判定区/标记/存活；自己 = 手牌明细/身份/pending 选项/特殊区；主公身份公开）。所有 handler 只接收 `SgsView`，**禁止读他人手牌、他人身份、牌堆顺序**（后期训练数据防泄漏的前提）。
4. 【P6.0 结构化历史（中期依赖，可先加字段不启用）】`state.rs::LogEntry` 增可选字段（`kind`/`action`/`card`/`targets`/`amount`，全部 `#[serde(default)]`，不改 `text` 文案、不 bump `SCHEMA_VERSION`），`push_log` 调用点逐步补齐结构化信息；供中期身份/手牌信念建模消费（当前 history 只有文本，无法可靠解析）。
5. 【P6.1 Baseline AI：评估函数】`ai/eval.rs`：①个体价值 = 体力/最大体力、手牌数与质量、装备、判定区负面（乐/兵/闪电）、翻面、标记；②团队价值 = 按身份后验把座位聚合成「我方/敌方/未知」（P6.1 先用静态身份：主公/忠臣=我方，反贼=敌方，内奸=条件敌友）；③节奏 = 本回合 sha_used/jiu_used、回合数、牌堆余量。输出可解释的分项得分（用于决策日志 candidates 排序与中期调参）。
6. 【P6.1 Baseline AI：行为树 + 覆盖全部 pending 形态】`ai/tree.rs` + `ai/handlers/*`：按 `pending.kind`（引擎已登记的 11 种：`target`/`respond`/`dying`/`discard`/`wuxie`/`pick_card`/`choice`/`choose_many`/`wugu`/`arrange`/`judge_rewrite`）与出牌阶段动作族（`play:`/`skill:`/`respond:`/`target:`/`discard:`/`choose:`/`pick:`/`arrange:`/`end_play`/`pass`）各一个 handler；优先级树 = **必选响应（濒死求桃/必闪/无懈）> 致死与保命 > 资源收益 > 节奏 > 空过**。每个 handler 返回「候选动作 → 分数」列表，未知 kind 走「安全推进」兜底（仿 `apps/verify-sanguosha.mjs` §安全推进：优先 pass/confirm，记录已用动作防同一牌反复 toggle）。
7. 【P6.1 Baseline AI：策略入口 + 剪枝】`ai/policy.rs` 实现 `game_engine_core::Policy` 的 `SgsPolicy`（确定性：同分按 legal 顺序）；`ai/prune.rs` 把完整合法集排序剪枝到 ≤26（`GAME_ACTION_CHOICE_LIMIT`），**保底项不可剪**：`pass`/`end_play`/当前必选响应动作；输出 `(candidates, full)` 供决策日志与中期搜索分支控制。`crates/game-engine-mcp/src/main.rs::bot_action` 按 `game_id` 分派：`sanguosha` → `sanguosha::ai::SgsPolicy`，其余保持 `RandomPolicy`。
8. 【P6.2 全覆盖回归】`ai/tests/*`：每种 `pending.kind` 至少 1 条定向用例（构造局面 → `decide` → 断言动作族合理、在合法集内、非空）；自对弈驱动 `crates/engines/sanguosha/examples/selfplay.rs`（对齐 las-vegas `selfplay.rs`：`--games/--players/--seed`，输出 JSON：终局率/非法动作数/步数分布/pending kind 覆盖集/身份胜率），并新增 `crates/engines/sanguosha/src/ai/selfplay.rs` 复用 las-vegas 的 `run_self_play` 形态。
9. 【P6.3 灰度验证通路（5 人局）】server 侧自动推进：`crates/server/src/game_routes.rs::execute_action` 成功后调用 `drive_bots`——循环「读 state → 取待行动 actor → 若 `seat.is_bot` 则 `SgsPolicy` 决策 + 引擎执行 → 直到人类回合/终局」，单请求步数上限 200（超限告警并停止）、每房间驱动锁（`Mutex<HashSet<room_id>>` 或 per-room `tokio::Mutex`）防并发双推进、每步重读 state 幂等。**驱动只在 server（单写者）**：`apps/agent-gateway` 的 `driveBots` 对三国杀直接跳过（避免 MCP/server 双进程双写）。
10. 【P6.3 群侧放开 `#加机器人`】`apps/agent-gateway/src/sanguosha-chat.ts` 的 `SGS_ALLOWED` 增加 `addbot`，`apps/agent-gateway/src/index.ts` 删除三国杀 `addbot/solo` 拒绝分支（改为「机器人补位（P6）」，并提示「机器人入局后由服务器自动行动」）；`#开始` 人数校验沿用引擎 `MIN_PLAYERS=5`（1 真人 + 4 机器人即可开局）。lobby 阶段由 MCP 写、开局后由 server 写，顺序不重叠（写入约定写进 plan 与 `docs/modules/game-engine.md`）。
11. 【P6.3 Web 侧呈现】`apps/agent-gateway/src/index.ts::buildGuidance` / `driveBots` 按 `game_id` 分派（现状写死 `d.sg.pending`/`phase=small_game`）：三国杀走 `sanguosha-chat.ts::sgsBoardText` 一行播报；`apps/web/src/view/sgs/*` 在机器人回合显示「机器人行动中…」等待态（轮询 10s 已存在），不暴露隐藏信息。
12. 【P6.4 决策日志】`crates/storage/src/lib.rs` 新增 `game_decision_log`（按 `docs/games/sanguosha/data-model.md` §5 字段）+ `append_decision_log`（写失败只告警不阻塞对局）；写点：server 每次动作后（`source` 按 `seat.is_bot` 取 `bot`/`human`）、MCP `bot_action` 后（`source='bot'`），`seq` 取动作返回的快照 `version`；采样/开关 `SGS_DECISION_LOG_RATE`（默认 1，0 = 关）。`state_digest` 可选（状态摘要哈希，供训练对齐）。
13. 【P6.4 回放与导出】`apps/scripts/sgs-export-decisions.mjs`：按 room/game 导出 JSONL（openid 做 sha256 前 16 位哈希；字段：room_id/seq/player_hash/source/legal/candidates/chosen/confidence/latency_ms），支持 `--out/--limit/--since`；`apps/scripts/sgs-replay.mjs`：`game_state` 快照 + `game_events` 逐步重放 + 叠加 decision log 时间线，支持断点续放（复用 `sgs-history.mjs` 的 SQLite 只读方式）。
14. 【P6.5 中期：读局面 + 身份判定 + 出牌质量】①`ai/threat.rs` 身份后验：基于动作族与目标做贝叶斯更新（打主公→反贼↑、救主公/替主公挡刀→忠臣↑、只打反贼→忠臣↑、内奸按局势平衡），主公身份公开作为先验锚点；②`ai/hand_belief.rs` 手牌推断：响应缺失（有杀不出闪/有杀不闪）、摸牌数、已亮明牌 → 维护每座位「有杀/有闪/有桃/有无懈」概率；③`ai/eval.rs` 接入 belief（盟友体力权重、敌方威胁权重），handler 选目标/选牌按敌友打分；选将 `setup:choose_general` 按身份倾向（主公高体/辅助、反贼爆发、内奸低调）；④关键决策一层搜索（候选 ≤8 时对杀/决斗/桃/无懈估算「命中率 × 收益 − 被反制风险」），**不做完整 MCTS**。
15. 【P6.6 后期：终极 AI（分阶段、每阶段可中止）】①数据管线：decision log + game_events → 训练集（可见状态张量 / 动作 id / 结果回报），导出脚本扩展 `--format=parquet|jsonl`；②自对弈吞吐：headless 批量（rayon 并行 + 确定性种子区间），目标 ≥1000 局/批；③完美信息蒸馏 / 先知教练：teacher 用全知 `SgsState` 的搜索/启发式打标，student 只用 `SgsView`（与 P6.0 不变量一致）；④策略网络（外部训练 PyTorch → ONNX，Rust 侧 candle/ort 推理，Cargo feature `nn` 可选），`SgsPolicy` 可切换 `heuristic|nn|mixed`；⑤评估：Elo / 胜率矩阵（vs random / baseline / 旧版本）、身份平衡、非法动作率 0、平均步数。
16. 【P6.7 工作台 + 预览的必要条件（仅做基座，不做设计器）】①`game_state_templates` 建表（`data-model.md` §5）+ `/internal/gameprops/templates` CRUD（仅本机，沿用 ADR-0017/0031 边界）；②`POST /internal/game/preview/{game_id}`：从模板快照造临时 room（`preview:<uuid>`，不写 `game_state`/`game_events` 真相源之外的库），复用现有 state/action 通路；③预览页 `GET /tabletop_game/:gameId/preview`：复用 P3 三分区视图组件 + 「单步执行 / AI 代打 / 回到模板」按钮；④场景注入（AI 定向调试关键）：模板可指定座位武将/手牌/阶段，引擎侧 `check_conservation` 校验。
17. 【P6.8 文档与里程碑】新增 `docs/games/sanguosha/ai.md`（分层架构 / SgsView 可见信息口径 / handler 分派表 / 剪枝口径 / 决策日志与训练数据 / 自对弈与评估指标 / 门禁命令）；更新 `docs/games/sanguosha/development-plan.md` P6 节（实施与验收记录）、`docs/modules/game-engine.md`（Policy 分派 + 驱动宿主 + 单写者约束）、`memory_palace/milestones.md`（M23 拆分为 M23a 短期 / M23b 中期 / M23c 后期）、ADR-0019 状态改为「已采纳（P6 修订：SystemOne 不参与走子）」并补 ADR-0032（AI 分层与可见信息不变量）。
18. 【用户裁定 2026-11-01（第 1 轮）】①SystemOne 不参与 P6 走子（仅离线对照）；②灰度两种形态都跑（1 真人 + 4 机器人真机；5 机器人全自动出 100 局指标）；③本轮**不产生任何 QQ 主动消息**（server 推进只改状态，Web 轮询可见，群内不播报机器人动作）→ 不触发主动消息门禁；④决策日志默认全量采样（`SGS_DECISION_LOG_RATE=1`）；⑤工作台在 `apps/props-admin` **单页应用内以 TAB 切换实现，不新增路由**（设计/模板/预览/决策日志四个 TAB，`v-show` 保留页内状态：当前模板、草稿、预览 room、步进位置）。
19. 【修订 P6.7（依裁定 ⑤）】工作台落位改为 `apps/props-admin/src/pages/WorkbenchPage.vue`（新增侧栏菜单项「工作台」，单页 TAB：模板 / 预览 / AI 调试 / 决策日志；TAB 切走不销毁组件，保留草稿与预览上下文）。预览区**以 iframe 嵌入 web 的三分区预览页**（同源 `/tabletop_game/{gameId}/preview?room=...`，复用 P3 渲染，避免在 Vue 里重写一套视图）；工作台负责「造局/注入场景/单步/AI 代打/回模板」控件，通过 `postMessage` 或直接调用内部 API 驱动；预览路由对 `props_admin` 白名单会话放行（不再要求 `game:{room_id}` token）。
20. 【用户裁定 2026-11-01（第 2 轮，全部 12 条通过）】①`#加机器人` 仅 lobby；②`LogEntry` 结构化字段全 `#[serde(default)]`、不 bump schema；③结构化历史为 P6.5 前置硬要求；④单请求推进上限 200 步 + 3000 步/局告警；⑤5 人局口径 = **全部已实现武将去重全量（149 位，`standard+wind_fire_forest_mountain+yijiang+jiexian`）+ 全卡牌（`standard+junzheng`＝160 张）**；⑥中期身份判定先做启发式贝叶斯后验（无训练），50 局人工标注后置；⑦写入 ADR-0032 硬约束（AI 只允许 `SgsView`）+ 隐藏信息不变性门禁；⑧MCP/server 双写轻量保护（server 校验 version 未落后；MCP 在 `play` 阶段除 `lobby:abort` 一律拒绝）；⑨自对弈性能 CI 10 局 debug ≤3 分钟、本地 release 100 局 ≤10 分钟；⑩预览路由对 `props_admin` 白名单会话放行（保留 `game:{room}` token 通道）；⑪工作台决策日志 TAB 只读 + 导出；⑫预览临时 room 不入库（内存态）。
