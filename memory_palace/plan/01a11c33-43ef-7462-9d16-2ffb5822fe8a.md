## 0. 目标

初始化一个基于 **QQ 群机器人**的桌游助手项目，按 Pi 社区最佳实践搭建目录结构、工作区设置与渐进披露文档体系，**不写业务代码**，仅完成脚手架与架构文档，并预留一个空的「拉斯维加斯」游戏引擎项目用于后续跑通全链路。

## 1. 技术选型（已确认）

| 模块/服务 | 语言 | 技术栈 | 理由 |
|---|---|---|---|
| QQ 机器人接入（qq-gateway） | Node.js (**TypeScript**) | QQ 官方 Node SDK（`@tencent-connect/qqbot-nodejs`）+ WS/Webhook | 官方 SDK 支持 Node |
| Web 资源展示服务器（web） | Node.js (**TypeScript**) | **Express** | 独立站点，轻量 |
| 其余后端模块 | Rust | **Axum**（tokio 生态） | 最流行、入门友好、文档与示例充足 |
| 运行形态 | Rust 模块 | **单进程多模块**（`crates/server` 组合各 lib crate） | 降低运维复杂度 |
| 消息总线 / 内存存储 / 缓存 | — | **Redis**（**Streams** + KV） | 兼做事件总线 |
| 持久化 | — | **SQLite**（sqlx / rusqlite） | 轻量、单文件 |
| 序列化 | Rust: serde / Node: JSON | JSON | 跨语言统一 |
| Monorepo | — | npm workspaces（Node）+ Cargo workspace（Rust） | 统一管理 |
| 本地依赖 | — | **docker-compose.yml 起 Redis** | SQLite 无需容器 |

## 2. 架构设计（已确认）

### 2.1 目标场景

- QQ **群**机器人（官方 bot.q.qq.com API v2 的群事件能力）。
- Web 为**独立站点**，短期 token 鉴权，路由约定：
  - 单页整合：`/tabletop_game/{gameId}/player/{qqid}?token=xxx`（同页展示全局资源与个人资源）

### 2.2 总览图

```
                    ┌──────────────────────────────┐
                    │        QQ 群（开放平台）        │
                    │  (WebSocket / Webhook / API)  │
                    └──────────────┬───────────────┘
                                   │ 官方协议 (群事件)
                    ┌──────────────▼───────────────┐
                    │  apps/qq-gateway  (Node/TS)   │  接入：收群事件 / 发群消息
                    └──────┬────────────────▲───────┘
                           │ raw QQ events  │ 发送出口 (qq.push)
                    ┌──────▼────────────────┴───────┐
                    │         Redis (Streams)        │  内存存储 + 消息总线 + 缓存
                    └──────┬────────────────▲───────┘
                           │ internal events│ 推送指令
                    ┌──────▼────────────────┴───────┐
                    │  crates/server  (Rust 单进程)   │
                    │   ├ bot-adapter     协议转换     │
                    │   ├ command-router  指令路由     │
                    │   ├ game-engine-core 引擎框架    │
                    │   ├ engines/las-vegas 首个引擎   │
                    │   ├ auth  鉴权（HTTP API）      │
                    │   └ push  全局/个人推送          │
                    └──────┬────────────────▲───────┘
                           │                │ HTTP 鉴权/资源查询
                    ┌──────▼──────┐   ┌─────┴────────┐
                    │  SQLite      │   │ apps/web      │ 独立站点(Express)
                    │  (持久化)     │   │ (Node/TS)     │ 公共/个人资源展示
                    └─────────────┘   └──────────────┘
```

### 2.3 模块职责

| 模块 | 位置 | 语言 | 职责 |
|---|---|---|---|
| qq-gateway | `apps/qq-gateway` | Node/TS | QQ 群协议接入：接收群事件、调用 OpenAPI 发群消息；原始事件写入 Redis Stream[qq.raw]；消费 [qq.push] 发送 |
| bot-adapter | `crates/bot-adapter` | Rust(lib) | QQ 群事件 → 内部统一消息事件（用户/群/内容标准化） |
| command-router | `crates/command-router` | Rust(lib) | 解析指令（前缀/@ 命令），按会话路由到游戏引擎 |
| game-engine-core | `crates/game-engine-core` | Rust(lib) | 引擎抽象（EnginePlugin trait）、注册表、对局状态管理 |
| engines/las-vegas | `crates/engines/las-vegas` | Rust(lib) | 「拉斯维加斯」引擎空项目，实现 EnginePlugin 骨架 |
| auth | `crates/auth` | Rust(lib) | 玩家身份、短期 token 签发/校验、个人资源归属校验（HTTP API） |
| push | `crates/push` | Rust(lib) | 全局广播 + 个人定向推送，写入 Redis Stream[qq.push] |
| server | `crates/server` | Rust(bin) | 单进程入口：组合各 lib 模块，提供 Axum HTTP API，消费 Streams |
| web | `apps/web` | Node/TS | Express 独立站点：公共/个人资源展示，经 auth 校验短期 token |
| shared | `crates/shared` | Rust(lib) | 内部事件、协议、公共类型定义 |

### 2.4 消息流（核心链路）

```
QQ 群事件 → qq-gateway(Node) → Redis Stream[qq.raw] → server(Rust)
   → bot-adapter 转内部事件 → command-router → game-engine
   → 状态变更 → push → Redis Stream[qq.push] → qq-gateway(Node) → QQ 群
```

### 2.5 Web 数据流

```
浏览器 → apps/web(Express) → server 的 auth HTTP API 校验短期 token
       → 资源查询 API → 读 Redis(缓存)/SQLite(持久) → 渲染返回
```
