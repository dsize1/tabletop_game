# 计划文档

## 计划

1. 裁定落账（2026-11-11 用户）：① AI 长局 → 采用**规则层终局设定**（不引入平局、不以「提高 AI 进攻性」作为门禁依据）；② 制霸**被动挑战本期实现**；③ 用户补充口径：**主公技不止制霸**——其他同势力角色也「有」该主公技（他人侧），要按通用机制处理，不能只给制霸开白名单。
2. 终局规则（规则层，真人与 AI 一致）：`ENDGAME_ROUND = 100`；`round > 100`（**第 101 轮起**，已裁定）【桃】与【桃园结义】的**回血效果无效**（牌仍可正常使用/结算/被无懈，但不再回复体力，日志+特效标「终局·回血无效」）；**濒死阶段不受限**（【桃】/【酒】/急救/酒池等救援照旧）。
3. 2.1 单点判定：`Game::endgame_no_heal()`（`kernel/mod.rs`，`self.round > ENDGAME_ROUND`）；禁止各处手写 round 比较（沿用「单出口」约定）。
4. 2.2 生效点：`kernel/card_play.rs` `Effect::Tao`（~1021）/`Effect::PeachGarden`（~1050）跳过 `flow::heal` → `push_log`（**实施偏差**：不新增 POutcome/fx 变体，避免动 presentation 契约与端侧映射，日志+视图徽标已足够可读）；**其它回血源一律不动**（已裁定：只限桃与桃园）。
5. 2.3 合法集与端侧：桃**仍可选**（已裁定：使用后无效，不从合法集移除）；AI 在 endgame 不再为【桃】打正分；`view.rs` 增 `endgame:{no_heal:true,round}`；`apps/web` 版图页顶部提示「第 100 轮后：桃/桃园回血无效」。
6. 2.4 文档与裁定：`rules.md`（终局节）、`rules-rulings.md`（新裁定）、ADR-0040（为什么不用平局、为什么只限桃/桃园）、`ai.md`（长局由规则收束，不靠 AI 进攻性）。
7. 主公技「他人侧」通用机制（**取代原「白名单 += zhiba」的 hack**）：主公技不是持有者独有的私有实现，而是「同势力共享、按各自模式开放」。
8. 3.1 数据：新增 `skills/lord.rs` 注册表 + 枚举 `LordSide { OthersActive / OthersTrigger / HolderRequest / HolderOnly }`，以 `code` 为键声明该主公技的他人侧模式。**不改 `SkillDef` 结构**（避免 ~296 个 def 机械补字段），注册表与 `SKILLS` 双向校验（覆盖 + 无冗余）。
9. 3.2 闸门改由注册表派生：删除 `skills/mod.rs` 的 `LORD_SKILLS_USED_BY_OTHERS` 硬编码；`lord_gate_ok()` = `others_side(code)` 允许他人 ∧ `same_kingdom(seat, holder)` ∧ 持有者存活；`legal_actions` 主动技闸门随之统一。
10. 3.3 门禁：`check:sgs2-registry`（或 conventions 新增 C7）要求**每个 `kind: Lord` 的 code 必须在 `lord.rs` 表里声明模式**（漏声明 → 红）；`docs/games/sanguosha/skills.md` 增「主公技他人侧」表（技能 / 势力 / 模式 / 实现状态 / 锚点）。
11. 3.4 13 个主公技核对结论（写入 skills.md，逐条写「为什么是这个模式」）：**OthersActive**=黄天、制霸；**HolderRequest**=激将、护驾；**OthersTrigger**=颂威、暴虐、立军、兴衰（现由持有者侧订阅、handler 内判他人条件，只补声明不改行为）；**HolderOnly**=救援、勤王、诏缚、血裔、若愚。
12. 制霸被动挑战（**复用注册 code `zhiba`**，不新增 code，避免 B14 对齐单「恰好相等」门禁破裂）：`zhiba` 从「仅持有者主动」扩为「持有者主动 + 其他吴势力挑战（他人侧 OthersActive）」。
13. 4.1 `can_zhiba` 双路径：持有者路径=现状（`turn.zhiba_used`）；挑战者路径=势力 wu ∧ 非持有者 ∧ 自己出牌阶段 ∧ `turn.zhiba_challenge:{seat} == 0` ∧ 双方均有手牌 ∧ 持有者存活且 `active(holder,"zhiba")`。
14. 4.2 handler 增 `stage=challenge`：压帧（actor=持有者）→「接受拼点 / 拒绝」；接受 → `kernel::pindian::start(challenger, holder, "zhiba")`；结算：挑战者没赢（点数 ≤ 持有者，平局算没赢）→ 持有者从弃牌堆获得两张拼点牌（已被取走则少拿）。跨角色询问沿用「立军/颂威」既有模式，**不需要 relay 通道**。
15. 4.3 计数（align/B14 Q1 裁定 A）：每个挑战者各自出牌阶段限一次 → `turn.zhiba_challenge:{seat}`；**拒绝也计次**；持有者主动拼点仍用 `turn.zhiba_used`。
16. 4.4 拒绝条件（已裁定）：**持有者一律可拒绝**（界孙策口径），不区分魂姿、不兼容标准孙策（该标的已下线）。
17. 4.5 AI：挑战者侧 `skill:zhiba` 正常主动技评分；持有者侧「接受/拒绝」启发式（可拒绝且手牌最大点数偏低时拒绝）——保持简单，避免引入新环。
18. 4.6 视图/文案：pending `choice` + `skill:"zhiba"`（「制霸：与孙策拼点（其可拒绝）」/「制霸：接受/拒绝挑战」）；`apps/web/src/view/sgs/skill-text.ts` + 浮层文案；技能栏不标注「他人可用」（已裁定：不改技能栏）。
19. 4.7 用例（`tests/b14.rs`）：接受拼点并结算 / 持有者拒绝 / 非吴不可挑战 / 同回合限一次 / 挑战者没赢（含平局）孙策得两张拼点牌。
20. 4.8 文档：`align/B14.md` §2 现实现改「主动+被动」、§7 断言补被动；`skills.md`（界孙策行 + 主公技表）；`rules-rulings.md`；`general-audit.md` 人工列备注。
21. 复跑门禁顺序：`cargo test -p sanguosha2` → `npm run check:sgs2-ai`（seed 1/2/3，**seed=3 第 0 局必须终局**）→ `npm run check:sgs2`（metrics/registry/decision-log/scenes/ai/conventions）→ `npm run sgs:check:fast`。
22. 兜底：若终局规则下 seed=3 仍不终局，**不自行加码**，回到「待确定事项」请示（候选：限制扩到其它回血源 / AI 进攻性 / 门禁 long-loop 分离）。
23. 本计划**不含主动消息**（无 pushActive / 无 reply_msg_id 推送），无需 `【主动消息已人工确认】`。
24. 真机回归（room 70c91b27，用户报 5 项）：①火攻展示可取消（v2 M1 引入 `escape`，v1 无）→ `escape_mandatory` ②五谷待办缺 `pending.data` → 特殊区无牌可点、卡住 → 补 pool/pickers/cursor ③同卡不同目标的合法动作标签重复（都叫「使用【杀】」）→ 标签加目标名（含转化牌）④恢拓重复记「回复 1 点体力」+ 重复 Heal 展示（实际只回 1 点）→ 去重 ⑤界面显示 openid → 客户端 `withDisplayNames()`（日志/待办选项/动作描述；bot:N→机器人N）
25. 顺带修：界火计 legal 含装备区牌但 execute 只认手牌（自对弈 seed=1 game 4 illegal）→ 一并放行；AI `sanitize_action()` 兜底（决策必须 ∈ legal，强制待办出口隐藏时不再给 pass）。
26. 同类排查（用户问 ①②③）结论：①强制步骤可取消——火攻（已修）+ 拆/顺「取消（不选牌）」+ 五谷「放弃（不取）」同类已改 `escape_mandatory`；拼点「取消（视为未赢）」保留（只能自损、不卡局，待裁定）②选项文案不可区分——`use:`/`convert:` 已带目标；同类抓到 燕语「结束重铸」两个同文案不同动作（done vs pass）→ `escape_with("done")`；新增自对弈门禁 `label_dups`（相同文案 + 不同动作签名）③pending.data 缺投影——无懈 root/layers、濒死 victim/hp、拼点 target、火攻 target/stage、拆顺 card/target、借刀 step 全部补齐；拆/顺浮层改用「回退全量按钮」（v2 `pick:<id>` 不匹配 v1 分组前缀 → 浮层曾空列表）
27. 固化：`docs/conventions/skill-spec-rules.md §25` 交互三不变量（强制出口 / 文案可区分 / pending.data 覆盖端侧读取）。
28. 拼点裁定落地（2026-11-11 用户裁定，`rules-rulings §47`）：拼点一旦成立**双方都必须出一张手牌**（取消出口 → `escape_mandatory`）；**任一方无可出的牌不能发起**（新增 `pindian::can_start`，`start()` 前提不成立时不压帧）；唯一例外=他人发起的挑战（界制霸）在拼点成立**之前**询问持有者可拒绝；专对（b8）对方无牌时不再给「拼点」选项。
