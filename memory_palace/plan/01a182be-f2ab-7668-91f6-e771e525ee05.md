## 待确定事项

- 【Q1 动作宿主（需确认）】现状：动作只能由 `game-engine-mcp`（agent-gateway 以 stdio 拉起）执行；server 只读快照。推荐 **A：server 内置执行**（`/internal/game/{gameId}/{roomId}/action`，本机单写者）——P3–P6 期间三国杀动作只由 Web/server 提交；MCP 仅用于建局/种子局（脚本），不与 Web 并发；P7 接入 Q 时统一走同一执行接口，避免双写（storage 无 CAS，last-write-wins）。备选 B：MCP 改长驻 HTTP（架构更干净但 P3 风险高）
- 【Q2 无 JS 文本态的提交方式（需确认）】ui-spec 要求无 JS 也能提交观星顺序 → 需要表单 `POST /tabletop_game/:gameId/action`（token 隐藏字段）。推荐做「文本态可读 + 表单提交（动作 id/pending 选项）」，不做无 JS 的完整交互；若不做提交，则把 ui-spec 该条降级为「仅展示」
- 【Q3 观星拖拽范围（需确认）】推荐：P3 先做「点击跨列 + 上移/下移」可完成全部排序并先验收；拖拽（长按激活 + 吸附 10%）同期实现但作为增强，真机阈值调优待人工实测（ui-spec §7.3 已预留）
- 【Q4 页面路由】推荐复用 `/tabletop_game/:gameId/player/:openid` + 按 `data.game` 分派渲染器（不新增路由，las-vegas 双模式零影响）；如需独立 URL 再加别名
- 【Q5 范围】Q 侧 `#开局 三国杀` / `#局面` / 链接（P7）不随 P3 提前；P3 只做 Web 页 + 本地脚手架链接
- 【待验证】WebView（Tauri 2/Android WebView）在复杂交互下的性能/兼容 → 按 ADR-0011/0020 属 P3 真机实测项，先用系统 Edge 移动视口模拟 + 人工手机浏览器验收


- 【已定 Q1 动作宿主 = A】server 内置执行：`POST /internal/game/{gameId}/{roomId}/action`（本机单写者）→ EngineRegistry 执行 → append_game_events + 快照；web `POST /tabletop_game/:gameId/action` 校验短 token 后转发。P3–P6 三国杀动作只由 Web/server 提交，MCP 仅建局/种子局（不并发）；P7 接 Q 时统一走同一执行接口（storage 无 CAS，必须单写者）

- 【已定 Q5 范围】Q 侧 `#开局/局面/链接` 不随 P3 提前，留 P7
- 【P8 边界（用户 2026-10-28）】Web 权限鉴定（QQ 扫码登录 → openId 认证、token scope、动作级校验）暂定 P8；P3 沿用现有 openid 绑定短 token。**引擎投影不是权限功能**：`/resources/game` 必须按 game_id 走 `EnginePlugin::public_state/player_view`，否则合法 token 也会拿到他人手牌/身份/牌堆顺序——此项仍属 P3.0 必修
- 【待定 Q2 无 JS 降级范围】三选一：① 只读文本态 + 提示「请启用 JS 交互」（不满足 ui-spec「观星文字顺序提交」）；② 完整无 JS 表单交互（所有动作/多步 pending 都能提交，工作量≈再做一层交互）；③ 只读文本态 + **pending 文本提交框**（输入动作 id 或 `arrange:<csv>` 后提交，满足 ui-spec 观星文字提交，工作量小）——**推荐 ③**
