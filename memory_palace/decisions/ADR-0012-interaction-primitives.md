# ADR-0012：交互原语分级（单选/多选/分区/级联/接力）与 Q 群消息侧冻结

- **状态**：已采纳（2026-10-19，用户裁定）
- **相关**：`docs/conventions/interaction-primitives.md`（本 ADR 的规范正文）、`docs/modules/game-engine.md`、`docs/games/las-vegas/legal-actions.md`、`docs/modules/board-view.md`；ADR-0010 / ADR-0011（端侧渲染与移动端形态）、ADR-0008（引擎契约与视图原语）；不涉及 ADR-0009（主动消息门禁，本 ADR 不产生任何主动消息）
- **结论一句话**：引擎侧只为「一次逻辑交互」声明**结构语义**（基数 × 可见性 × 步数与主体），**控件与实现由消费端决定**；**Q 群消息侧冻结**（继续用编号清单 + `#选 N`，不因本语义改动）；级联仅限「同一主体 + 连续」

## 背景

1. 引擎当前对外只有扁平列表 `Action { id, description }`（`crates/game-engine-core/src/lib.rs`），没有任何交互类型字段；消费端只能渲染成「编号清单 + 输命令」。
2. Q 群侧已把这套做到极致（`#选 N` / `#放 N` / `#选 代码`，尽量少打字），用户明确表示**满意且今后不再改**。
3. APP / WEB 端要的是「一次会话内完成一次交互」，因此必须先把「一次逻辑交互」的结构说清楚，否则端侧无法选控件（单选？复选？穿梭框？向导？）。
4. 现状下多步交互只有 `pending.stage` 字符串（`sg.rs`）和 id 前缀隐含结构，没有统一口径，也没有文档；新增第 3 个游戏时极易各自发明。
5. 已存在的两处真实差异必须被区分：F2/H2/F1/H1 是**同一个人连续多步**；A1/G1 是**下注者 → 左手玩家 → 赢家**的跨人链。二者混在一个「多段式」说法里会误导端侧做「一次提交」。

## 决策

### 1. 交互原语（三轴）

| 轴 | 取值 |
|---|---|
| **基数** | `one`（取 1）/ `many`（取任意子集，无补集语义）/ `partition`（二分：选中→A 堆、未选→B 堆） |
| **可见性** | `plain`（明文）/ `masked`（密文：引擎只下发一次性代码，真义仅在本人 `player_view`） |
| **步数与主体** | 单步 / **级联**（同一主体 + 连续）/ **接力**（跨主体）/ **异步等待**（跨阶段或需他人动作） |

- **保留 `many`**（用户 2026-10-19 明确）：当前拉斯维加斯无实例，但作为原语保留，不做「暂不需要就删」的裁剪。
- 「加密」**不**是第三形态，只是 `vision = masked` 的正交轴（A1 = masked one；G1 split = masked partition）。

### 2. 级联判定（4 条裁定）

1. **级联 = 同一主体 + 连续**。只有同时满足这两条的多步交互才可归为级联；级联的价值是**一次消息 / 一次会话内完成交互**。
2. **主体不同，或不能连续（异步）→ 都不是级联**，必须拆成独立交互（接力 / 异步等待）。
3. 若对「A 堆 / B 堆」**分别设置会让交互过于复杂**，合适的控件只有**穿梭框**（即 `partition`）。
4. 同 2：异步 / 跨主体一律不套级联。

### 3. Q 群消息侧冻结（核心约束）

- Q 侧继续只消费 `{id, description}` 与下标（`#选 N` → `legal[n-1].id`）；**不接受、也不需要**读取交互描述符。
- 因此引擎若要落地描述符，**只允许追加 `#[serde(default)]` 字段**，且：
  - **不得**改动现有 `id` 与 `description`；
  - **不得**改变 `legal_actions` 的顺序与条数（`#选 N` 依赖下标）；
  - **不得默认**把级联合并成「一键完成」动作（会改条数/顺序并让提示退化）；若将来要做，必须默认关闭 + 显式开关 + 保留分步 id。
- 多步交互在 Q 侧**就是多轮 `#选 N`、多条消息**——这是最终形态，不是待优化项。

### 4. 端侧「一次提交」不阻塞、也不提前做

级联在 APP/WEB 侧要「一次提交」需要批量执行原语 `execute_actions(room_id, player_id, [action...])`（整链校验、失败不留部分状态）。**本期不实现**，列为端侧立项前置缺口；在此之前端侧也只能逐步提交。

## 理由（取舍）

| 方案 | 结论 |
|---|---|
| 维持「扁平 Action 清单」不定义交互类型 | 否：端侧无法选控件，第三个游戏起会各自发明结构 |
| 把「加密」当独立形态 | 否：与基数正交，会造成形态爆炸（加密单选/加密多选/加密分区/加密级联…） |
| 把 A1/G1 的跨人链也叫「级联」 | 否：违反「同一主体」判定；端侧会误做「一次提交」，把别人的选择也代填 |
| 给 G1 的 A/B 堆各做一套多选 | 否：交互过于复杂，正解是穿梭框（`partition`） |
| **三轴原语 + Q 侧冻结** | **采纳**：语义够用（覆盖全部 16 个小游戏）、端侧可映射控件、Q 侧零风险 |

覆盖校验（现状全部可表达）：单步 9 类；级联 F1（2 步）、F2（3–4 步含条件步）、H1（2 步）、H2（1–3 步含循环边）；接力 A1、G1；异步等待 B1；无交互 A2/C1/D1/E2/C2。

## 影响

- **本期零代码改动**（纯文档 + 决策落盘）。规范化正文见 `docs/conventions/interaction-primitives.md`。
- `docs/modules/game-engine.md`：新增「交互语义」一节与约定项（扩展只增不改、改交互形态需同步文档）。
- `docs/games/las-vegas/legal-actions.md`：新增 §6 交互类型标注表；§5 补「只增不改」约束。
- `docs/modules/board-view.md`：注明网页当前**只读**（不提交动作）、`partition` → 穿梭框、级联 → 向导（规划）。
- **Q 侧守卫**：任何触碰 `legal_actions` 顺序/条数或 `description` 文案的改动，视为违反本 ADR。
- 后续待办（未排期）：`execute_actions` 批量原语；`get_interaction` 只读原语（需按 `docs/conventions/mcp-primitives.md` 补能力描述符）；`masked` 的 token 粒度是否拆细。
