# ADR-0018：武将回合设计工作台 —— 复用 n8n 做图编排，引擎只做仿真与校验

- **状态**：提案·待评审（2026-10-25）
- **相关**：`docs/games/sanguosha/plan.md`（三期需求）、`docs/games/sanguosha/development-plan.md` P5、`docs/games/sanguosha/data-model.md`（模板表）、ADR-0013（n8n/LangGraph/DeepAgents 分层）、ADR-0016（规则内核刚性）、ADR-0017（中台技术栈）、ADR-0020（Web 优先与视图三分区）
- **结论一句话**：工作台**复用自托管 n8n** 作为有向图编排宿主，节点/边只描述「设计」；预览页调用真实引擎做逐帧仿真与规则校验；**n8n 不参与线上对局执行**；若自定义节点无法满足逐步仿真，撤退到 Vue Flow 自研。

## 背景

1. 立项文档：武将描述不严谨、规则复杂，很难靠提示词让 AI 开发武将；需要一个用有向图编排「回合内（判定→摸牌→出牌→弃牌）与回合外（技能响应）」的工作台。
2. 工作台需要：合法动作列表与规则校验（**刚性，不可通过中台修改**）；预览页能跑完整一轮 5 人局；局面/资源模板可保存、复制。
3. 项目已有 n8n（`deploy/n8n` + `docker-compose` profile）用于 dev shadow 工作流，具备可视化编排、自定义节点（HTTP/Code）、版本与执行记录。
4. 现有中台（ADR-0017）将持有武将/技能元数据与模板表；引擎（ADR-0016）将提供合法动作/规则校验原语；Web 交互基座（P3，ADR-0020）先于本工作台完成，预览页复用其三分区视图。
5. 需要避免两种极端：把流程图当运行时（规则不可控、难测试）；完全自研图编辑器（成本高、重复造轮子）。

## 决策

### 1. 分工边界

| 组件 | 职责 | 明确不做 |
|---|---|---|
| n8n（自托管） | 图编辑、节点/边存储、版本、执行记录、人工审核入口 | 不参与线上对局；不写游戏状态真相源 |
| `props-admin`（P5 增加工作台路由）或独立 `apps/sgs-workbench` | 工作台入口、模板 CRUD、预览页、只读调用引擎 | 不实现规则校验；不直接改状态 |
| sanguosha 引擎 | 合法动作、规则校验、逐步执行、事件产出 | 不读取 n8n 工作流作为运行时规则 |
| `crates/server` | 模板表、流程设计绑定表、只读查询代理 | 不承载图执行 |

### 2. n8n 节点语义（约定）

- 节点类型（首期）：
  - **阶段**：回合开始/判定/摸牌/出牌/弃牌/结束/回合外；
  - **触发**：技能事件（如 `damage_after`、`card_used`）＋条件表达式；
  - **询问**：向引擎发起 pending（选目标/选牌/确认）并等待选择；
  - **结算**：调用引擎只读校验/执行 API；
  - **分支/汇合**：条件边。
- 边 = 时机流；不允许回边形成无界循环（需要循环时用引擎的 pending 队列而非图循环）。
- 自定义节点通过 HTTP 调 `props-admin` 后端（server）的只读 API：`GET /internal/sgs/flow/meta`、`POST /internal/sgs/flow/validate`、`POST /internal/sgs/flow/simulate-step`；鉴权用管理员白名单 + 内部 token。
- 工作流与武将绑定：`sgs_flow_designs(general_code, workflow_id, workflow_version, status)`；`status` 人工推进（draft → simulating → verified → archived）。

### 3. 预览与模板

- 预览页加载 `game_state_templates.snapshot`（`GameState` JSON），逐步调用引擎：
  1. 展示局面/资源（复用 Web 桌面页视图组件或同一 API）；
  2. 显示当前合法动作（刚性来自引擎）；
  3. 人工/脚本选择动作 → 引擎执行 → 展示新状态与事件；
  4. 支持保存/复制模板、从回放导出模板（`source='replay:<room_id>@<seq>'`）。
- 预览测试目标（验收）：至少 1 个完整 5 人局一轮，覆盖回合内与回合外技能。
- 模板管理页放在中台（ADR-0017）：列表、复制、删除、导入导出。

### 4. 落地流程（工作台 → 代码）

1. 在工作台画出武将流程并仿真通过；
2. 导出「设计稿（图）+ 测试夹具（状态/动作/期望事件）」；
3. 由开发（或 dev 执行器）按设计稿写 Rust 技能实现 + 用例；
4. 用例进仓库，CI 跑通后工作流置 `verified`。

> 明确：工作台**不生成可直接上线的代码**（首期）；避免「图即规则」的可审计风险。成熟后可评估代码生成，另立 ADR。

### 5. 撤退点（硬约束）

满足任一条件即改用 Vue Flow 自研图编辑器（`apps/sgs-workbench`）：

- n8n 自定义节点无法在一次执行内**逐步暂停/恢复**并读写外部状态（工作流执行模型限制）；
- 无法把「合法动作列表 + pending 队列」实时回显到画布；
- 自托管 n8n 的升级/依赖成为部署负担（例如需要独立 DB/队列且与现有 compose 冲突）；
- 图规模达到 n8n 画布性能瓶颈（>200 节点，待实测）。

撤退只替换「图编辑 UI」，数据模型（`sgs_flow_designs` + 模板表）与引擎 API 不变。

## 理由（取舍）

| 方案 | 结论 |
|---|---|
| 自研图编辑器（Vue Flow / React Flow） | 备选：可控但与 n8n 功能重复，首期成本高 |
| 纯文本 DSL / YAML 描述流程 | 否：不直观，难让非开发者参与评审 |
| n8n 作为线上运行时 | 否：规则内核刚性（ADR-0016）、延迟/事务/回放不可控、许可证与运维风险 |
| **n8n 做设计宿主 + 引擎做仿真 + 人工落代码** | **采纳**：复用现有设施、保留规则刚性、可撤退 |

## 影响

- P5 需要：n8n 自定义节点包（内部）、server 只读仿真 API、模板表、工作台路由；**依赖 P3 Web 视图**（预览复用公共区/个人区/特殊区）。
- 需要为引擎增加「按步执行 + 合法动作」的只读接口（可复用 MCP 原语，经 server 代理）。
- n8n 的许可证（Sustainable Use License）用于内部自托管属允许范围；**上线前仍需法务/用户确认**（标记待验证）。
- 工作台不进入线上关键路径：n8n 故障不影响对局。

## 依据与验证状态

- n8n 现有部署：`deploy/n8n/workflows/dev-shadow.json`、`docker-compose.yml`（profile），**已验证可用**（M16）。
- 「n8n 逐步暂停/恢复 + 外部状态回显」能力：**待验证**（P5 第一周做技术验证，决定是否触发撤退点）。
- 200 节点性能阈值：**待验证**（工程经验值，不作为实现约束）。
- 许可证结论：**待确认**（用户/法务），不作为上线放行依据。
- 本 ADR 不新增外部数值约束（无频控/配额）。
