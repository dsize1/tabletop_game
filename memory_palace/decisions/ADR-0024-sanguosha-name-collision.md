# ADR-0024：三国杀同名武将替换口径（界限突破 / 界标 25 将）

- **状态**：已采纳（2026-10-30，P4.4.2 批次 1 落地；batches: 一将成名 8 将 + 数据扩包）
- **关联**：ADR-0016（引擎内核）、ADR-0018/0020（工作台/多端，不涉及）、`skills.md` §2.7/§2.8、`development-plan.md` P4.4.2
- **影响范围**：`crates/engines/sanguosha`（`data.rs` 生成、`lib.rs::prefer_jiexian` 选将池、`Config.general_packs` 包组合）

## 1. 背景

「界限突破」（jiexian）与标准包/风林火山存在**同名武将**（如「界刘备」对应「刘备」）。若两者同时启用，会出现：

- 选将池里同一角色名两份，主公候选/发牌语义混乱；
- 同名武将技能 code 相同（如 `rende`）但效果不同（界版强化），`skills_of(general_code)` 已按武将绑定，但**文档/门禁**按「武将行 + 技能 code」登记，需要口径避免冲突；
- 旧对局（`Config.general_packs = ["standard"]`）不能因新增包而改变行为。

## 2. 决策

1. **武将 code 独立**：界化武将使用新 gid（`sgs_hero_299+` 等），`GeneralDef.pack = "jiexian"`；武将名保留「界」前缀（`界刘备`）。不修改、不覆盖原武将数据。
2. **技能 code 复用**：界化武将沿用同名技能 code（`rende` / `liegong` …），差异通过 `skills_of(武将 code)` 分别登记 + 引擎内按武将/`has()` 分支实现。文档按「武将行」登记（`check:sgs-skill-docs` 已支持同名技能多行）。
3. **选将池同名去重（口径 A「界优先」）**：当 `Config.general_packs` 同时包含 `jiexian` 与来源包时，
   - 以「界化武将名去掉前导『界』」得到原名集合；
   - 原名相同的**原版武将**从选将池剔除，只保留界版本；
   - 仅启用 `jiexian` 而不启用来源包时不受影响（界版本照常进池）；
   - 实现：`lib.rs::prefer_jiexian(codes)`（纯函数，单测覆盖）。
4. **实现门槛**：`skills::general_ready` 仍然是硬门槛——未实现的界化武将不进池；因此界标 25 将**分批落地**，去重逻辑在界标 25 将实现后自然生效。
5. **旧局兼容**：`Config.general_packs` 默认仍是 `["standard"]`；`data.rs` 全量登记 232 位（含未实现），旧快照 `#[serde(default)]` 解析不受影响；新增包 key 不影响旧包对局行为。
6. **包组合**：`lobby:set_general_packs` 支持 `standard` / `standard+wind_fire_forest_mountain` / `+yijiang` / `+jiexian` 及其组合；标签与「可用 N 位」按去重后的选将池计算。

## 3. 已知边界

- 界标 25 将（界刘备/界关羽/…/界诸葛亮）**本批未实现**（滞后完成）；本批只落地数据 + 数据扩包 + 一将成名 8 将。未实现界化武将不进池，因此「界优先去重」在选将池的实际效果需待界标 25 将实现后可见（纯函数已单测）。
- 同名去重按**名字**匹配（去掉前导「界」），不按技能/势力；若将来出现「界」前缀之外的同名变体（如「神」），需扩展映射表。
- 界化武将的同名技能若需不同交互（界面/合法动作），由技能实现内按武将 code 分支；不引入「技能版本」字段。
- 旧对局不改写 `general_packs`；重放/快照按原 `config` 解析。
